08 · 輸入輸出與 Pipe ​

檔案系統處理名稱、目錄和資料放置；I/O system（輸入輸出系統）處理如何跟裝置交換資料。WUWAOS 提供 UART 終端、可選 GUI TTY、行程間管道與 VirtIO 區塊磁碟這幾條路徑。

UART 終端 ​

drivers/uart/uart.c 以 volatile 指標讀寫 0x10000000 的 UART（序列埠）裝置暫存器。輸出前輪詢是否可寫；讀取時檢查是否收到資料。kernel/io/console.c 負責輸出格式、路由與核心診斷，不直接操作 UART MMIO。volatile 保留硬體存取，不等於鎖或完整記憶體同步。

一般 shell 使用行輸入：收集字元、處理 Backspace，等 Enter 才完成 read。fan 使用 raw console（逐 byte、不回顯輸入），因此按方向鍵不必先按 Enter。

canonical line input 接受 Ctrl+D（ASCII EOT）作為 EOF：空行時 read 回 0；已有字元時先回傳目前字元，不附加換行，下次 read 再按 Ctrl+D 才回 EOF。這讓 cat 可由終端輸入文字並以 Ctrl+D 結束；raw mode 將 Ctrl+D 當一般輸入 byte。

raw console 同時只能有一個持有者；行程退出、被終止或成功 exec 時釋放。它是自訂介面，不是完整 POSIX termios。

圖形桌面 Terminal ​

有 VirtIO GPU、tablet 與 keyboard 時，kernel 桌面目前提供一個固定大小 Terminal 視窗。圖示開啟後建立另一個 shell process，其 FD 0/1/2 綁到 generation-checked GUI TTY endpoint；UART shell 綁到另一個固定 endpoint。每個 endpoint 各自持有輸入／輸出佇列、raw owner 與 CR/LF 狀態，避免 fan 或 workstate 讀取 GUI 按鍵時搶走 UART 輸入。Shell ps、pcb、vmstat 的核心列印依 fd 1 的 endpoint 暫時路由；開機與裝置診斷仍寫 UART。UI 目前仍只有一個 Terminal view，尚未提供多視窗。

TTY endpoint 是本專案自訂核心物件，不是 PTY master/slave ABI。OFD_TTY 持有 generation handle；dup/fork 共用 OFD 引用，session 結束後舊 handle 失效，所有 FD 引用釋放前不重用 endpoint slot，重用時 generation 遞增。圖示關閉只隱藏並保留 shell；exit 或空行 Ctrl+D 結束 shell。設計與 QEMU 驗收見 Spec 30。

核心 kernel/io/io.c 擁有 FD/OFD、pipe 與 I/O 路由；kernel/io/tty.c 擁有各 endpoint 的 queues、session refs、raw owner、CR/LF 狀態與輸出 consumer。註冊的 consumer 將 GUI console bytes 送到 ui/terminal/vt.c 更新 ANSI VT model，再由 ui/terminal/renderer.c 繪出字元與終端游標；pipe bytes 不經 GUI TTY。桌面視窗/合成在 ui/desktop/desktop.c，鍵盤映射在 ui/input/keymap.c；process loop 經 boot 註冊的 callback 輪詢 UI。這些仍在 S-mode 核心內執行。完整模組與資料通道見 Spec 33 及程式碼架構圖。

等待時資料放在哪裡 ​

kernel/io/io.c 不能在核心函式裡一直等到某個行程有資料，否則其他 Ready 行程沒有機會前進。尚未完成的操作會記在 PCB 的 io_operation、io_fd、io_buffer、io_length、io_count，行程改成 Waiting。

行程在 process_block_io 內保存核心上下文，切到獨立排程器堆疊。排程迴圈與返回前的 process_resume 輪詢可完成的 I/O，將結果存入 PCB 的 io_result 並喚醒行程。再次派發後從原核心函式恢復，io_read／io_write 正常回傳結果，再由 syscall_dispatch 填使用者 a0；不再由輪詢端直接代填 a0。使用者資料不一定常駐 RAM，搬移時由安全複製介面逐頁載入，錯誤明確回報。見核心上下文切換。

這裡的「阻塞行程」不等於「裝置中斷」：目前 UART 仍以輪詢觀察，不是中斷驅動。

真實的位元組管道 ​

每個行程有 8 格 FD table，初始 0／1／2 對應 console input／output／error；全域 16 個 OFD（開啟檔案描述）保存檔案 offset 或 pipe endpoint。dup、dup2 與 fork 共用 OFD，因此共用檔案 offset；exec 保留描述，exit／kill 逐格關閉。console 描述是特殊核心端點，不占 OFD 槽。open 支援唯讀、唯寫、讀寫、建立、截斷與附加旗標；O_APPEND 每次寫入時取目前 EOF。WUFS 開啟中的 inode 若被 rm、rm tree、cp 覆寫或 truncate，會回 busy，避免開啟描述指向已回收或換代 inode。

每個 pipe 使用 256-byte ring buffer（環形緩衝區）。read_at、write_at 是讀寫索引，count 記錄目前資料量；索引前進至尾端後繞回。

管道滿時寫入者等待；reader 讀走資料後輪詢會喚醒寫入者。空管道且仍有寫入者時，reader 等待；所有寫端關閉且資料讀完才得到 EOF（資料結束）。沒有讀取者時，寫入回報 ERR_BROKEN_PIPE。

每 byte 入／出緩衝區 O(1)，搬移 N bytes 為 O(N)，另外可能包含多次阻塞與恢復。端點引用透過 OFD 引用計數在 dup／fork 繼承、close／exit／kill 關閉時更新；多餘端點關閉後才會出現 EOF 或 broken pipe。

drivers/virtio/block.c 從 FDT 探索現代 VirtIO-MMIO 裝置，每顆磁碟有自己的請求與佇列狀態。以磁碟標頭辨識 WUFS 與 Swap，不依賴裝置順序。目前磁碟請求同步輪詢完成；尚無磁碟排程、非同步請求或快取。

每個已提交的 512-byte 請求以硬體時間計數器計時，預設超過 5 秒且仍未完成，就印出裝置、角色、操作、磁區與等待時間，然後停止核心。逾時不是取消成功，因此不返回上層、不回收或重用請求緩衝區。門檻在 drivers/virtio/block.h 調整；一次頁面交換含八筆磁區請求，不共用一個 5 秒總預算。這是目前 WUWAOS 的停止策略，尚無裝置重設與恢復。見 Spec 12。

shell 支援 echo hello | cat、ls | cat、最多三階段、<、> 與 >>。舊 writer | reader 也由一般 parser 執行，讀到既有示範訊息與 EOF。cat 可讀檔案或 stdin；只在 console 輸出且末尾不是 LF 時補顯示用換行，pipe 和檔案輸出不改資料。直接執行的外部 ELF 不帶 argv，沿用 Spec 26 ABI。每階段最多 8 個參數 token，整行最多 128 bytes；此為 WUWAOS 固定容量設計，不是完整 POSIX shell。
