11 · workstate 即時監測 ​

在 WUWAOS shell 輸入 workstate，會開啟終端全螢幕的行程監測，每秒更新、每頁最多 8 個行程，按 n／p 切換頁面、q 或 Q 返回原 shell。第一張的 CPU 顯示 sampling，取得下一個時間區間後才顯示百分比。

畫面有哪些資料 ​

欄位意義
PID／PPID、NAME、STATE行程編號、父行程、內建程式名稱與真實 PCB 狀態，包含 Waiting／Zombie
CPU%最近兩次畫面快照之間，被派發執行的時間比例
CPU ms從建立以來累計的派發執行時間，fork 子從零開始，exec 保留
RSS(K)目前仍在 RAM 的使用者頁面，單位 KiB，不含核心堆疊與頁表
MEM%RSS 除以平台的總 RAM，目前為 128 MiB；小行程可能顯示 0.0%，可看 KiB
SWAP(K)已換出而不常駐 RAM 的使用者頁面，單位 KiB

行程使用 ASCII 表格顯示，數字靠右、名稱與狀態靠左；標題與資料共用欄寬。數值變長時欄位會擴展，避免截斷；若總寬超過終端視窗，請加寬 PowerShell 視窗。

上方 RAM used 包含核心、頁表、OpenSBI 與 FDT 等保留區，不等於各列 RSS 相加。Reserved/static 是未進入動態配置池的部分。Swap slots 也包含常駐頁仍保留的交換區備份，所以不一定等於表格的 SWAP KiB 總和。

CPU 是怎麼算的 ​

CPU task 是排程工作占用率：包含行程被派發期間的使用者程式、syscall 與缺頁處理，排隊或阻塞等待不算。它不是宿主 Windows／QEMU 的 CPU 負載。idle/scheduler 包含排程開銷與目前 UART／期限輪詢；硬體可能仍在忙等，不能用這個值推論節電。

各列按 PID 配對計算，避免回收後重用 PCB 欄位產生錯誤差值。整體累計保留已退出行程的時間，因此剛退出或回收時，整體百分比不一定等於目前可見各列總和。

監測者本身也需要資源 ​

workstate 是獨立內嵌 user image。Shell fork 後 exec 此 image，所以監測行程會占一個 PCB，表格中的 workstate 列包含畫面刷新開銷。它取得 raw console，檢查鍵盤後以 sleep_ms 休眠 50 ms，再檢查更新時間；不在使用者模式持續忙等一秒。按 q 正常返回 shell；若被 kill，核心也會釋放 raw ownership 並退出 alternate screen。16 個 PCB 額滿時命令顯示 fork 錯誤。

workstate_snapshot 在 VM Gate 內讀取 PCB 與頁面用量，離開 Gate 後才複製結果到使用者記憶體；遇到其他 VM 操作時會在原 syscall stack 等待。定時等待仍由核心排程迴圈檢查 deadline；runtime 磁碟等待已會讓出 CPU，但 VM Gate 競爭、CPU 繪圖或其他行程的時間片仍可能延後畫面更新與 q 的處理，不是即時期限保證。同一終端的其他輸出可能交錯，下次更新會重畫。
