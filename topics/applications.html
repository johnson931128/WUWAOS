10 · Shell 與 fan 編輯器 ​

ls 不帶參數時列出目前目錄；rm 路徑 刪除檔案或資料夾（資料夾需輸入 Y 確認），cp /absolute/source /absolute/destination 複製檔案。cls 會要求終端清除畫面和捲動歷史，保留 WUFS 檔案；捲動歷史是否真的清除取決於終端對控制序列的支援。命令範圍與限制見 Spec 18。

核心提供能力，使用者程式把能力組合成操作。WUWAOS 的 shell 與 fan 都是 U-mode（使用者模式）程式，透過 syscall 操作行程、終端與檔案。

Shell 如何執行命令 ​

管理命令 fallback 由 user/shell/shell.c 讀入最多 126 個字元，切成最多 4 個 token（以空白分隔的單位）再比對命令。通用 echo／cat／ls／pwd pipeline 由 user/shell/shell_exec.c 另行解析，最多 3 個 stage、每 stage 8 個參數，支援引號與檔案重導向。整行解析為 O(L)，L 是輸入長度；目前沒有腳本與一般背景工作控制。

在提示字元輸入 help，每行會列出一個命令及其參數，右側對齊用途說明；行程、檔案與記憶體操作用空白行分隔。<path> 可是相對或絕對路徑，<page> 從 0 起算。格式與驗收見 Spec 14。

操作主要流程
ps／pcb進核心查詢行程狀態
ls／cat／write／rm／cp以路徑呼叫 WUFS 服務
cls透過終端控制序列清除畫面及捲動歷史
run counterfork 子行程，再 exec 指定內建程式 ID
echo／cat／ls／pwd 管線parser 建立多個 stage，pipe／fork／dup2 接上標準 FD，再 wait
fan 路徑fork → exec fan 並傳入路徑 → 父 shell 等待
vmstat／mem查詢與操作使用者記憶體

命令和 syscall 沒有一對一關係。以 fan 為例，一次編輯操作可能多次讀取按鍵、輸出控制碼，最後才寫入檔案。圖形桌面 Terminal 也啟動同一份 shell image，只是將 FD 0/1/2 綁到 GUI TTY；fan 與 workstate 不必改成圖形程式，就能在該視窗以 raw byte 模式運作。

Fan 現在透過 fs_replacefile 安全替換整份檔案：核心先建立完整新內容，再於同一 journal transaction 切換名稱。一般錯誤保留 buffer；若回報 Save uncertain，代表可能已提交，編輯器保留 dirty 狀態並禁止再次儲存，需重啟／重新開啟確認實際內容。這項 2026-11-08 修改未執行操作測試；舊 Spec 09 的驗收不涵蓋此路徑。

命令是如何被「吃進去」的？ ​

以在 /home/user 輸入 cat note.txt 為例：

  1. UART（序列埠）或 GUI TTY 接收終端字元；核心 I/O 完成一行後，shell 的 read 拿到文字。
  2. shell 先由 shell_exec.c 解析可串接命令、引用文字、管線與檔案重導向；其他管理命令再由 tokenize／command 分派。這些都是 WUWAOS 使用者程式，不代表每個命令都是 syscall。
  3. cat 使用通用 open/read/write 描述號介面。API 將 syscall 編號放入 a7（系統呼叫編號暫存器），參數放入 a0 等暫存器，執行 ecall（進入核心的指令）。
  4. 硬體依 stvec（監督模式例外入口位址暫存器）轉到例外入口；核心保存行程狀態後，syscall_dispatch（系統呼叫分派器）依編號選擇檔案讀取。核心使用該行程 PCB 的 CWD（目前工作目錄），將 note.txt 視為 /home/user/note.txt，再逐層查找 WUFS。
  5. 核心將資料和結果交回 shell，shell 透過輸出 syscall 印出；sepc（例外返回指令位址暫存器）跳過剛執行的 ecall，最後 sret（返回使用者模式指令）恢復執行。若找不到檔案則顯示錯誤。

cd 呼叫 chdir 改變本行程 PCB 的目錄；workstate、fan fork 子行程再 exec 各自的內嵌 image。管線支援 echo、cat、ls、pwd 及無參數 ELF command stage；run <path> 也可從 WUFS 執行符合限制的靜態 RV64 ELF。目前沒有 PATH 搜尋、外部 ELF argv 或任意 Linux ELF 相容。shell 使用最多三個 stage、每階段最多八個參數 token、128-byte 命令列。

目錄操作 ​

指令功能
pwd顯示目前目錄
cd、cd ~切到 /home/user
cd notes、cd ~/notes以相對路徑或家目錄路徑進入
cd ..、cd /前往上一層或根目錄
cd -返回前一個目錄並印出路徑
ls列出目前目錄

提示字元顯示完整目前路徑，例如 wuwaos/>、wuwaos/note>；若取得目錄失敗則顯示 wuwaos?>。初始 shell 從 / 開始。spawn、fork 或 pipe 新建的子行程繼承目錄，exec 保留；之後各行程各自管理。目標不存在或不是目錄時不會改變位置。規格與驗收見 Spec 19。shell 原始碼、系統呼叫分派。

三份獨立使用者映像 ​

Makefile 將 shell、app、fan 分別連結為 ELF，再轉成 binary 嵌入核心。kernel/exec/user_image.S 保存原始內容，VM 在需要時載入對應頁面。

因此 fan 是真正的獨立行程，但還不是由 /bin/fan 磁碟執行檔載入。user/lib/entry.S 將初始參數交給 user_main，返回值再交給 exit。

C 程式是在哪裡編譯的？ ​

目前在主機的 WSL Ubuntu 執行 Clang（C 編譯器），產生 RISC-V 機器碼；QEMU 再載入並執行已編譯的核心。這稱為交叉編譯：編譯器執行的位置與產物的目標 CPU 架構不同。

fan 可以寫 .c 檔，但 WUWAOS 尚無系統內 C 編譯器。現已支援從 WUFS 執行符合固定布局的靜態 RV64 ELF；尚需補齊工具鏈與相關檔案介面，才可能在 WUWAOS 內編譯。設計與驗證見 Spec 26，長期規劃見 Spec 21。

從 WUFS 載入 ELF ​

在 QEMU 關閉時，主機可以使用 tools/make_disk.py --install 把既有相容的 ELF 匯入 WUFS，之後在 shell 使用 run /bin/shell.elf（路徑依安裝位置決定）。相對路徑也支援。父 shell 等待執行完成並回收子行程；目前無程式參數或 PATH 搜尋。

載入器先檢查 ELF 標頭與每個載入段，建立新的頁表並複製檔案內容，全部成功後才切換行程。執行期間可正常換頁，即使原檔之後刪除，行程仍使用自己的內容。只支援特定 RV64 靜態格式與固定地址，並非一般 Linux 相容環境；操作步驟及限制見 Spec 26。

fan 的文字資料結構 ​

user/apps/fan/main.c 用連續 byte 陣列存放最多 2048 bytes ASCII／LF 文字，cursor（游標）是陣列中的位移。

例如 abc 的游標在 b 前面，插入 X 時，先把後段 bc 向右移，再放入 X，得到 aXbc。刪除則反方向搬移。插入／刪除最壞 O(N)，對小型文字檔容易理解與管理，不需要複雜樹結構。

一個終端上的全螢幕介面 ​

Shell、fan 與 workstate 的互動畫面經 UART 或 GUI TTY 輸出 ANSI 游標定位、清行與色彩控制碼。GUI 終端是至少 80×24 的 kernel-rendered cell surface；不等於 POSIX PTY 或完整視窗系統。參考開機流程中的桌面 Terminal、Spec 28 與 Spec 30。

編輯器持有 raw console，shell 等待子行程，不會同時讀走你的按鍵；背景行程輸出仍可能干擾畫面，尚無完整前景工作隔離。

限制與參考 ​

UTF-8、超大檔案與不支援的控制字元會拒絕開啟，以免截斷覆寫。既有 Tab 以 > 顯示並保留，新 Tab 插入空白。目前沒有 undo、搜尋、Vim 命令模式與原子儲存。
