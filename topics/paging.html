按需分頁、置換與 Swap ​

對應現行規格：〈08 · 頁面、虛擬記憶體與 COW〉。

程式保留了一段合法虛擬位址，不代表每一頁現在都占用 RAM。Demand paging（按需分頁）在真正需要資料時才準備頁面；RAM 頁框不足時，再透過 Page replacement（頁面置換）與 Swap（記憶體與磁碟交換）騰出空間。

一次合法缺頁 ​

  1. CPU 取指令、讀取或寫入，發現 PTE 不存在，觸發缺頁。
  2. trap_handler 讀 scause（陷阱原因）與 stval（相關位址），交給 vm_handle_fault。
  3. VM 檢查是否位於合法區域，且允許這種存取。
  4. resident_page 取得頁框；從原始程式映像、零頁或 Swap 完整載入內容。
  5. 成功後才公布有效 PTE，同步轉譯，返回使用者模式。
  6. sepc（例外指令位置）維持原值，CPU 重試同一指令。

原因 12 是取指令缺頁，13 是讀取缺頁，15 是寫入缺頁。非法位址和寫入唯讀頁不會因為「發生缺頁」就獲准配置。

寫入時複製（COW） ​

fork() 建立獨立的子頁表。兩個行程可以先共用已在 RAM 的 4 KiB 頁框。原本可寫的映射會暫時清除 PTE 的 W，並以 Sv39 軟體保留位元 RSW[0] 記住 COW 狀態。

Store fault（原因 15）以 stval 找到該頁。核心確認原權限允許寫入後，才拆分頁框或恢復寫權限。原本唯讀的程式碼頁仍保持唯讀。user_copy_to() 寫入使用者記憶體時也先處理 COW，例如 read() 把資料寫進使用者的 buffer。

讀實作可從 vm_fork、resident_page、resolve_cow 開始。引用、置換與驗證結果見 COW 規格。

步驟 1 / 14：1 · FIFO 找到 eligible victim。等待換出

固定教學資料，不是即時 QEMU trace。FIFO 掃描範圍包括最多 16 個 process 與 exec 備用空間；核心頁及 page table 不置換。

示意假設 victim 為 dirty、沒有既有 Swap 副本，開始交易時配置新 slot 12；失敗情境模擬第 3 個 sector 出錯，實際故障可能在任一 sector。clean 且可由映像／零頁重建的頁可直接丟棄；已有有效 Swap 副本則可重用，不需另配 slot。

核心的 vm_handle_fault 取得 VM Gate 後會跨越可能睡眠的 swap_write。原 fault caller 等待磁碟時，另一個 process 若也發生 page fault，會等待同一 Gate；scheduler/UI poll 是 no-wait context，若配置需要置換，會在修改 PTE 或送 I/O 前回 ERR_BUSY。互動中的失敗情境假設沒有其他 eligible victim；實際 evict_one 在某頁寫失敗並 rollback 後，還會繼續掃描下一個候選，僅當沒有其他候選可用時才回 ERR_IO。換出成功或回復完成後，Gate 仍由外層 fault scope 持有，直到外層處理完需求頁或錯誤才 leave。模型只表現這些同步關係，不代表 process 可任意操作 VM metadata。

補充分頁表記錄什麼 ​

kernel/mm/vm.c 的 VmSpace 保存程式來源、heap 結尾與每頁 VmPage；每頁記錄實體位址、交換槽位、修改狀態、入駐次序與暫時固定次數。

VM 的可重入 scope 序列化頁表與 resident metadata 的建立、複製、fault、置換及查詢；scheduler/UI poll 是 no-wait context，若配置必須置換會在修改 PTE 或送出磁碟 I/O 前回 BUSY。Dirty page 換出前先保存並撤銷舊 PTE、執行 sfence.vma，再進行可能睡眠的 Swap I/O；其他行程碰到該頁會 fault 並等候 VM Gate。失敗時恢復原 PTE，保留 dirty RAM 作有效副本。

PTE 是 CPU 查找的結構；補充表是核心用來決定「缺頁時去哪找資料」的 metadata（管理資料）。兩者用途不同。

何時置換、如何選頁 ​

預設全系統使用者常駐預算為 128 頁，也就是 512 KiB。頁框預算達上限，或底層沒有可用實體頁時，VM 嘗試置換。

FIFO 掃描補充表，選最早入駐且符合置換條件的實體頁框。讀寫命中不改入駐次序。共享映射使用相同入駐序號，任一映射被 pin 或所屬位址空間正在其他 Hart 執行時，暫時跳過該頁框。核心與分頁表不參與置換。

  • clean（未修改）且可從映像／零頁重建：直接丟棄。
  • clean 且已有 Swap 副本：保留槽位，不必重寫。
  • dirty（已修改）：預留所需槽位後撤銷該頁框的全部映射，並同步轉譯。每個需要寫出的映射使用獨立 slot，完整寫入各自的 8 個磁區後才一起提交並回收頁框。失敗時恢復整組 PTE，釋放本次新增槽位，並保留 dirty RAM。這段期間 VM Gate 保持持有，kill 也會延後。

修改狀態合併軟體記錄與硬體 PTE_D（已寫入標記）。缺頁處理會暫時 pin（固定、禁止換出）當前指令可能跨越的程式碼頁，避免資源不足時指令頁與資料頁互相淘汰、永遠無法完成重試。

磁碟交換 ​

專用 build/wuwaos-swap.img 預設 16 MiB，標頭占 4 KiB，其餘為 4095 個 4 KiB 槽位。它與 WUFS 分開；重啟後不恢復舊行程。

kernel/mm/swap.c 用 bitmap（位元圖）管理槽位。槽位從 1 編號，0 代表沒有槽位。槽位 n 從磁區 8*n 開始，一頁逐次讀寫八個 512-byte 磁區。

原始碼：kernel/mm/swap.c／kernel/mm/swap.h，由 GitHub main 管理，本站不內嵌來源檔。

欄位、限制與主要函式 ​

課程以 FIFO queue 解釋「最早進入 frame 的頁面先離開」；WUWAOS 沒有每行程的實體 FIFO queue，而是掃描補充記錄中的 arrival，取最小且未 pin 的常駐頁。 觀念參考：notes/ch10 Virtual Momory.md · 缺頁處理、dirty bit、§10.4.2 FIFO。

WUWAOS 欄位用途與本實作語意
VmPage.physical非 0 表示目前有 RAM frame；為 0 時可能在 Swap，也可能由映像／零頁重建。
VmPage.slot1-based Swap slot；0 表示沒有已指派 slot。新 slot 先配置，I/O 成功後才寫進 page metadata。
VmPage.arrival頁面進入 RAM 時遞增；FIFO 命中不更新。跨所有 VmSpace 比較。
VmPage.pins非 0 時不可置換。fault handler 也會 pin 可能跨頁的指令 code page。
VmPage.dirty、PTE D軟體修改狀態與硬體 dirty bit 合併判定；dirty 頁不能直接丟棄。
EvictionMapping.saved暫存該頁框每個映射的 leaf PTE，供 I/O 失敗時整組復原。
frame_refs、resident每個使用者頁框的映射引用，以及全系統常駐實體頁框數。預設預算 128 個，最少 8 個。
Swap bitmapswap.c 的槽位配置圖；slot 由 1 起算，0 不代表磁碟位置。

換出失敗時，VM 保留原本 RAM 副本；換入失敗時，不公布只讀到一部分的頁面。沒有 Swap 仍可按需配置與丟棄可重建頁，但不能無條件換出修改過的資料。

配置與生命週期 ​

sbrk 只保留 heap 合法範圍，第一次存取才分配頁框。fork 保留尚未配置頁的按需載入語意，為已換出頁建立獨立 Swap 副本。exec 切換映像、縮小 heap 與退出清理會解除原本的映射。最後一份引用解除時才歸還實體頁框。

目前共用限制由 include/vm_limits.h（GitHub） 定義。每頁 4096 bytes，heap 起點為 0x1000000，每個行程最多有 256 個 heap 頁。全系統預設有 128 個常駐頁框的預算，最小可設 8 頁。

錯誤與限制 ​

非法缺頁回 -14，沒有資源回 -12，Swap I/O 失敗回 -5。無法補頁就結束該行程。磁碟等待會讓出 CPU。逾時時核心會要求重設裝置，確認裝置停止後才隔離並回錯，否則保留 DMA 緩衝區並停止執行。換出失敗會恢復原 RAM 映射。若裝置已離線，僅存在 Swap 的其他頁仍可能無法換入。既有 QEMU 回歸已驗證共享換出與 I/O 失敗復原。 驗收與尚未驗證的情境

頁框共享來自 fork，Swap Slot 仍各自持有。縮小 heap 只釋放不再涵蓋的整頁；部分頁縮小再擴張不保證清零。常駐頁保留交換區副本，空 heap L0 表保留至空間銷毀。

觀念參考：notes/ch10 Virtual Momory.md · 缺頁處理步驟與 §10.4.2 FIFO。WUWAOS 目前實作及資源不足、唯讀交換區、非法存取等既有驗收見 Spec 10；未實際耗盡全部 128 MiB，也未注入部分磁區讀取失敗。
