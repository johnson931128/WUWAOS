Spec 04：WUWAOS 開機 ASCII 展開動畫 ​

本文件保留初版井字號圖案與驗收；目前螢光色塊粗體字、70 欄與 35 格展開見 Spec 13。

目標與範圍 ​

使用者希望開機以 ASCII ART（文字字元圖案）顯示 WUWAOS，從中央逐漸向兩側展開。 在既有 QEMU virt 核心加入啟動畫面，結束後保留完整字樣並照常進入 shell（命令列介面）。 不變更行程管理、pipe（資料管道）或系統呼叫，不新增測試程式碼，不自行 commit / push。 前一版規格保留於 SPEC-03-shell-pipe.md，早期里程碑保留於 SPEC-01／02。

設計與演算法 ​

  • 新增 kernel/splash.c/h，只負責啟動畫面，由 main.c 在例外入口安裝後、核心初始化訊息前呼叫。
  • 以 # 與空格組成 7 行、52 欄的 WUWAOS，左右留白，適合至少 80 欄的 ANSI 終端。
  • 動畫以中心為軸，每次多揭露左右各一欄，外側尚未揭露的字元以空白遮罩；26 個畫面逐步顯示完整字樣。
  • ANSI escape sequence（終端控制碼）清除舊啟動畫面、回到畫面起點重繪、暫時隱藏游標；最後還原游標。不逐行捲動堆疊動畫。
  • 使用 rdtime（讀取硬體時間計數器指令）控制每格約 45 ms，最後停留約 200 ms；不是依主機 CPU 速度估算的空迴圈。
  • QEMU virt 時基固定按目前平台的 10 MHz 設定；不新增 timer interrupt（計時器中斷）或延遲系統呼叫。僅開機短時間輪詢等待。
  • 圖案逐欄遮罩，單格 O(H×W)，H=7、W=52，總空間固定；中心展開是揭露圖案，不是縮放字型。
  • 畫面清除會移走先前 OpenSBI 的可見文字；核心啟動資訊在動畫後重新從下方輸出。

修改檔案與步驟 ​

  1. 新增 splash.c/h、調整 main.c 與 Makefile 的核心來源清單。
  2. 更新 README 與 CODE_GUIDE 的啟動行為、檔案功能與平台限制。
  3. 建置並在實際 QEMU 終端確認中心到完整圖案的連續畫面、游標還原、shell 可輸入。
  4. 將實際驗收填入本文件，保留之前尚未提交的改動。

驗收條件 ​

  • 原始碼可建置，沒有未解析符號。
  • 啟動時由窄中央區域逐步揭露至完整 WUWAOS，畫面位置固定且不因換行捲動。
  • 結束後保留圖案並恢復游標，wuwaos> 可執行 ps 等正常指令。
  • 未新增測試程式碼；非 ANSI 或小於 80 欄終端不在本次驗收範圍。

實際驗收紀錄 ​

  • Clang 建置成功，沒有新增測試程式碼。
  • 實際 QEMU ANSI 終端呈現中央狹窄區域到完整 WUWAOS 的逐格展開，最後保留完整字樣與平台副標題。
  • UART 原始輸出紀錄確認 26 次定點重繪，動畫區域沒有 NUL 字元，結束時有游標還原控制碼。
  • 每行圖案均為 52 個字元，實際畫面沒有超過 80 欄或逐格捲動。
  • 動畫後進入 wuwaos>，實際輸入 ps 得到 shell PCB 列表，exit 正常結束，再離開 QEMU。
