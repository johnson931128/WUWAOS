06 · 同步工具怎麼做 ​

WUWAOS 提供使用者程式可請求的 Mutex 和 Semaphore。核心另外用 Gate 保護檔案系統、虛擬記憶體和 Block 裝置的長操作，並以事件通知等待者。它們都能讓等待者暫停，但保護的對象和喚醒後的動作不同。

先決定要保護哪一件事 ​

Mutex 用來保護一段操作，鎖住後可更新一組必須一致的欄位。Semaphore 用來記錄可消耗的份數。例如容量為 4 的佇列可用一個初值 4 的 Semaphore 表示空位，再用一把鎖保護實際入列。空位的數量和佇列內容的互斥各有用途。

等待可以靠重複檢查，也可以由核心把呼叫者移到 Waiting，讓其他執行緒使用 Hart。短小的底層共享核心鎖有自旋路徑，使用者同步物件等不到資源時可以阻塞。用哪種等待方式，取決於保護範圍、持有時間與目前能否睡眠。

使用者程式的 Mutex 與 Semaphore ​

工具核心維護的資料等待與喚醒
Mutex有一位擁有者的鎖，用來保護臨界區。持有者完成後才能解鎖。WUWAOS 用執行緒身分判斷誰有權解鎖。目前擁有者是一條執行緒。有擁有者時加入等待佇列。解鎖只能由擁有者發出，解鎖後喚醒隊首。原擁有者退出時標記鎖已受損，等待者收到 SYNC_ERR_OWNER_DIED。
Semaphore記錄可用份數的同步物件。等到一份資源時減一，歸還或生產資源時加一。即使當下沒有等待者，已增加的份數也會保留。還可以取用幾份資源。wait() 在數量大於零時取走一份，否則等候。post() 加回一份並喚醒隊首，即使當下無人等待，這份資源也會保留。

兩種物件共用 8 格核心表，程式以 handle（物件編號）操作。等待者被喚醒後會重新嘗試取得資源，因此喚醒順序是 FIFO，取得資源的順序仍受後續派發影響。尚有持有者或等待者時不能銷毀物件。同一執行緒重複鎖住自己的使用者 Mutex 會回傳錯誤。

跟著 demo sync 看兩次等待 ​

父行程先持有 Mutex，並建立初始值為 0 的 Semaphore。子行程一開始嘗試拿鎖，因父行程還持有而進入等待。父釋放 Mutex，子取得鎖、釋放鎖，接著在 semaphore_wait() 等待。父行程 post() 後，子行程重新取得執行機會並消耗那一份。畫面上的訊息能看出互斥、計數與排程分別在哪一步發生。 同步示範程式

核心的 Gate 與事件 ​

KernelGate核心內部用來保護操作邊界的鎖。擁有者可以配對地重複進入和離開，其他執行緒會等待或在不能睡眠的路徑收到忙碌結果。 以 Thread 和 TID 辨識擁有者。同一擁有者可以再次進入，每次進入需配對離開。其他執行緒遇到已占用的 Gate，可以等擁有者釋放。中斷處理與排程器輪詢等不能睡眠的路徑，遇到忙碌 Gate 時回傳 ERR_BUSY。

事件來源核心用來通知等待者的物件。Generation 區分同一欄位的不同使用週期，sequence 表示通知有沒有更新。等待可以帶期限，結果留給被喚醒的執行緒收取。 用 generation 辨識物件的這一次使用，用 sequence 記下自上次查閱後是否發生通知。等待者可同時設定 deadline（最後等到的時間）。通知、逾時或取消會把結果留下，讓執行緒回來後知道等待為何結束。共享核心鎖序列化短暫的核心狀態更新，Gate 則保護可能跨越執行緒睡眠的操作邊界。

可以用 Shell demo sync 觀察 Mutex 和 Semaphore。Core 測試覆蓋 Gate 所有權與 TID 的行為，QEMU 既有驗收覆蓋實際 I/O 事件等待和喚醒。 同步實作 · Gate · Event · 同步規格 · 非同步 I/O 驗收
