WUWAOS 現行規格 ​

這套規格從啟動系統開始，接著沿著 read() 等使用者程式操作，追蹤核心怎麼接手、何時換一條執行緒、資料從哪裡來，以及發生錯誤時如何收拾。實作以 main 的 3a3b273 為核對基準。每章列出原始碼入口和對應的驗收紀錄。

章要回答的問題
00 · 專案簡介與系統架構主機、QEMU、OpenSBI、核心和使用者程式各做什麼？
01 · 如何執行：啟動、建置與驗證如何從原始碼或現有 Windows Release 啟動？
02 · 從使用者程式進入核心系統呼叫、缺頁和中斷怎麼進核心、怎麼回去？
03 · 行程與執行緒誰持有資源？fork、exec、wait 和 join 各做什麼？
04 · 誰先跑：排程、狀態與多 HartCPU 怎麼選下一條執行緒，等待中的執行緒怎麼回來？
05 · 為什麼要同步競爭和漏接喚醒是怎麼發生的？
06 · 同步工具怎麼做Mutex、Semaphore 和核心等待機制各保護什麼？
07 · 資料怎麼進出：I/O 與磁碟read() 如何接到檔案、Pipe 或終端，磁碟請求怎麼完成？
08 · 頁面、虛擬記憶體與 COW位址怎麼轉譯、缺頁怎麼補、何時共享或換出頁框？
09 · 資料怎麼存下來：WUFS 與磁碟復原檔案如何命名、寫入，重啟時如何重播交易？

名詞表集中收錄正文使用的術語。原有 SPEC 的編號、網址與驗收繼續保留在原始規格與驗收紀錄，程式檔案的分工可查程式碼導覽。

「已實作」表示可在目前原始碼找到該行為。「已驗證」表示連結中的紀錄實際跑過該情境。「未驗證」表示仍缺少該場景的運行結果。本次整理沿用既有執行證據，重新驗證的是文件建置和連結。
