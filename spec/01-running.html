01 · 如何執行：啟動、建置與驗證 ​

你可以直接使用已有的 Windows CLI Release，或在 Windows 的 WSLWindows 上的 Linux 執行環境。WUWAOS 的原始碼可以在 WSL 內的 Ubuntu 用 Linux 工具建置，再由 QEMU 執行編出的 RISC-V 系統。 Ubuntu 內建置目前原始碼。前者功能以該版本的發行說明為準，後者會編譯工作目錄中的原始碼。

從原始碼啟動 ​

WSL Ubuntu 需有 Clang、LLD、LLVM 工具、Make、Python 3 和 RISC-V QEMU。從專案根目錄的 PowerShell 執行：

powershell
wsl -d Ubuntu -- make run-disk
1
入口實際開機路徑
make run-diskOpenSBI 交給 Flash 載入器以 QEMU 模擬 Flash 作為來源的小型開機程式。WUWAOS 的磁碟開機路徑由它讀取 WUFS 內的 /boot/kernel.elf，把控制權交給核心。，再由載入器從 build/wuwaos-cli.img 取出 /boot/kernel.elf。預設只掛這一顆 WUFS 磁碟，載入器要求 journal先存一筆交易要寫入的新磁區內容，再標記交易已提交，然後才改動正式位置。若在改動途中中斷，下次掛載可按已提交的資料重做。 無待重播交易。
make runQEMU 直接載入 build/kernel.elf，同時掛上 build/wuwaos.img 與 build/wuwaos-swap.img。可用於 Swap 測試或依復原紀錄操作。
make run-gui直接載入核心並接上 VirtIO 圖形與輸入裝置，進入圖形桌面。

要在 CLI 指定兩個 Hart硬體可獨立執行指令的一個位置，具有自己的暫存器和指令位置。QEMU 設定 -smp 2 時，WUWAOS 可在兩個 Hart 上各派一條執行緒。，可執行 wsl -d Ubuntu -- make run-disk CLI_HARTS=2。預設是一個 Hart。新磁碟通常由主機工具建立成 WUFS0002，磁碟載入器也識別 WUFS0003。若已有磁碟出現未重播交易，請依復原流程處理。 Makefile · 磁碟載入器

用現有 Release 啟動 ​

解壓 Windows CLI Release，按發行說明安裝 QEMU，然後在解壓目錄用 CMD 執行 WUWAOS。這條路徑執行的是發行版的預編譯核心。 Windows CLI Release

確認已進入系統 ​

看到 wuwaos/> 後，在 QEMU 裡輸入 help、ps 或 ls /。終止 CLI 的 QEMU 可按 Ctrl+A 後按 X。Shell 的 exit 則只結束 Shell。

既有自動化驗收從 WSL 執行 python3 -B tools/test_kernel_cli.py。工具會另建測試磁碟，涵蓋直接開機、Flash 開機、2／3 Hart、管線和 WUFS 重播。 CLI 測試 · 既有驗收

從韌體交接到 Shell ​

沿著開機順序逐步查看 OpenSBI、載入器、核心和 Shell 如何交接。 開機流程補充

make run-diskOpenSBI 先交給 flash 載入器。載入器從 WUFS 取得核心並載入 RAM，再跳到 _start。

步驟 1 / 7

QEMU virt

主機用 QEMU 建立單 hart、128 MiB RAM 的 virt 機器，並以預設 OpenSBI 韌體啟動。

磁碟開機將 boot-flash.img 接成唯讀 flash，另接一顆 VirtIO 磁碟。直接開機由 -kernel 預載 build/kernel.elf 到 RAM。
