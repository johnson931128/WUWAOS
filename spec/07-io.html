07 · 資料怎麼進出：I/O 與磁碟 ​

read(fd, buffer, n) 的 fd 是行程內的一個編號，叫檔案描述符使用者程式用來讀、寫或關閉某個 I/O 來源的整數。相同數字在不同的行程內可以指到不同物件。。核心用它找出資料來自哪裡。對程式來說，資料可能來自磁碟上的檔案、另一個程式的 Pipe，或終端機輸入。

FD、Pipe 和終端 ​

  • FD 與 OFD：每個行程有自己的 FD 表。一般開啟物件另有一筆 OFD核心保存一次開啟操作的記錄，包含來源、讀寫位置與引用。多個 FD 可指到同一筆記錄，因此共用位置。，保存物件種類和讀寫位置。dup()、dup2() 和 fork() 可以讓不同 FD 指到同一筆 OFD，因此共享讀寫位置。關閉 FD 會減少 OFD 引用。
  • Pipe：核心用一段有上限的緩衝區傳遞 bytes。空 Pipe 還有寫端時，讀者等待；資料讀完且最後一個寫端消失時，讀取回傳 0。寫入端遇到沒有讀者時會收到 ERR_BROKEN_PIPE。Shell 用 dup2() 把各個程式的標準輸入或輸出接到對應端點。
  • 終端：UART 和圖形 TTY核心管理的終端輸入輸出端點。WUWAOS 可把 Shell 接到 UART，也可接到圖形桌面上的 Terminal。 可供 Shell 收字符、寫輸出。存取終端的 FD 仍透過相同 I/O 入口，核心依端點種類把資料送到對應裝置或畫面。

用 FD／OFD 互動教學操作 open()、dup() 和 fork()，觀察哪些描述符共用讀寫位置。

一次磁碟讀取的路徑 ​

  1. io_read() 取得來源物件，WUFS 找出需要讀的磁區磁碟讀寫的編號單位。WUWAOS 的 WUFS 和 Swap 使用 512 bytes 磁區，一個 4 KiB 的 Swap 槽位占八個磁區。。WUFS 的磁碟格式見第 09 章。
  2. VirtIO虛擬機與模擬裝置交換請求的介面。WUWAOS 的磁碟驅動把操作放進 VirtIO 佇列，裝置完成後回報結果。 Block 驅動準備磁碟請求，寫入裝置佇列後通知 QEMU。請求包含磁區、操作與傳輸緩衝區。
  3. 開機可用輪詢由程式主動檢查「完成了嗎」，例如在開機時重複讀取磁碟狀態。中斷是裝置主動通知核心，兩條路徑可以共用完成檢查。等完成。一般執行期間，呼叫者透過核心事件等待，讓出 CPU。裝置完成由 PLIC平台層級中斷控制器。裝置送出外部中斷後，核心透過它辨識是哪個來源，再交給相應的處理函式。 派發中斷，或由輪詢路徑走共用的完成檢查。
  4. 呼叫者恢復、收取結果，再把已取得的資料寫到使用者緩衝區。驗證使用者位址與寫入觸發 COW 的行為見第 08 章。

每顆 Block 裝置的請求和傳輸緩衝區持有至完成收取。逾時時先確認裝置已安全重設，才能隔離裝置並回傳錯誤。無法確認裝置停止存取緩衝區時，核心停止執行以保護記憶體。這是磁碟失敗路徑，應用程式也要依 read()／write() 回傳的實際長度處理部分傳輸。

既有 CLI 驗收涵蓋管線、檔案讀寫和 IRQ，Block reset 故障情境的驗證邊界見整合紀錄。 I/O 實作 · Block 驅動 · FD 與管線規格 · Block 整合紀錄

動手觀察 ​

  • 磁碟非同步 I/O展示請求送出後，呼叫者如何讓出 CPU，裝置完成後如何恢復。
  • 終端與管線說明 UART、圖形 TTY 與 Pipe 的資料路徑。Shell 與 fan有能在 QEMU 重現的操作。
