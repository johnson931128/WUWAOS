00 · 專案簡介與系統架構 ​

WUWAOS 是一個跑在 QEMU virt 上的 RISC-V 64 位元RISC-V 是 CPU 指令和執行環境的規格。RV64 表示採用 64 位元的 RISC-V 基礎架構。WUWAOS 的核心和使用者程式由主機工具編譯成這套指令。教學作業系統。你可以從終端機啟動程式、用管線傳送資料、讀寫磁碟，再沿著程式碼追蹤這些操作如何通過 CPU、核心和裝置。

從主機到使用者程式 ​

層次負責什麼
主機工具Clang 和 Make 在主機組譯、編譯與連結 RISC-V 核心及使用者程式。Python 工具準備磁碟映像。
QEMU在主機上模擬另一台電腦的工具。WUWAOS 使用 QEMU 的 virt 機器來取得模擬的 RISC-V CPU、記憶體、UART 和磁碟裝置。 與 OpenSBIRISC-V 的開機韌體。它先在比核心權限更高的 M-mode 啟動，交出控制權後仍可透過 Supervisor Binary Interface（SBI）提供計時器與跨 Hart 等服務。QEMU 提供模擬的 CPU、RAM 和裝置。OpenSBI 是開機韌體，也提供給核心設定計時器、啟動其他 Hart 等服務。
WUWAOS 核心管理行程、執行緒、頁表、檔案和裝置。核心與使用者程式藉由系統呼叫使用者程式請核心代辦工作的介面。例如 read() 透過 ecall 把編號和參數交給核心，完成後取得讀了幾個 bytes 或錯誤碼。交接。
使用者程式Shell 執行命令與管線。fan 編輯檔案，workstate 顯示行程與資源用量。相容的靜態 ELF可執行檔與程式資料的容器格式。WUWAOS 的 ELF 載入器讀取檔案中描述位址、大小和權限的資料，建立新程式映像。可執行的使用者程式還要符合 WUWAOS 的系統呼叫約定。 也能從 WUFSWUWAOS 自有的磁碟檔案系統。它把路徑和檔案內容對應到磁碟中的目錄、inode 與磁區。各版本的差異見檔案系統規格。 載入。

例如，Shell 執行 cat /note 時，程式向核心請求開檔和讀取。核心透過 WUFS 找出檔案資料，再請磁碟驅動取回。程式最後把 bytes 寫到終端。這條路徑用到後文的系統呼叫、排程和 磁碟 I/O。

平台與範圍 ​

現行目標是 QEMU virt、128 MiB RAM 和 OpenSBI。文字操作介面（CLI）使用 UART傳送和接收序列資料的裝置。WUWAOS 的 CLI 使用 QEMU 提供的 UART 收鍵盤輸入、送出終端文字。，圖形目標另外接 VirtIO虛擬機與模擬裝置交換請求的介面。WUWAOS 的磁碟驅動把操作放進 VirtIO 佇列，裝置完成後回報結果。 GPU 和輸入裝置，讓圖形 Terminal 可執行 Shell。核心能執行符合 WUWAOS 系統呼叫約定的靜態 RV64 ELF，Linux 的執行檔和動態連結器不在支援範圍。
