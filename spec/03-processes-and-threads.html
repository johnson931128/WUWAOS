03 · 行程與執行緒 ​

把程式跑起來時，核心建立一個行程一份正在運作的程式及其資源。行程用 PID 辨認，持有自己的位址空間、檔案描述符和工作目錄，可以包含多條執行緒。，用 PID 辨認。行程持有頁表、檔案描述符、工作目錄等資源。實際在 CPU 上前進的是執行緒在 CPU 上前進的一條指令流程，用 TID 辨認。同一行程內的執行緒共用記憶體，各有自己的堆疊與暫存器狀態。，用 TID 辨認。每條執行緒有自己的堆疊、暫存器和執行位置。同一行程內的執行緒透過同一份頁表看到共用資料。

核心記錄保存什麼
PCB核心為每個行程保存的記錄，包含 PID、父 PID、頁表位置、檔案描述符、工作目錄和退出狀態。行程的 PID、父 PID、頁表、檔案描述符、工作目錄、生命週期與退出狀態。
TCB核心為每條執行緒保存的記錄，包含 TID、所屬行程、執行狀態、等待原因、堆疊及切換時要保存的狀態。執行緒的 TID、所屬行程、狀態、等待原因、使用者／核心堆疊和保存的執行進度。

同一個程式可以跑出什麼 ​

磁碟上的 ELF 是可載入的程式映像。啟動兩次時，各自建立行程和位址空間，即使兩份記憶體的虛擬位址看起來相同，也能映射到不同頁框。在同一行程建立第二條執行緒時，兩條執行緒則共用行程資源。共享可寫資料需要同步，暫存器與堆疊仍分別保存。

以兩條執行緒共同操作一個行程內的緩衝區為例，程式只需傳遞緩衝區指標。若工作分到兩個不同的行程，可使用 Pipe 等行程間通訊機制，把資料交給另一邊處理。傳遞資源的方式和 CPU 如何逐條派發是兩個獨立的問題。 行程結構 · 執行緒結構

行程如何建立、換程式和退出 ​

操作呼叫後會發生什麼
spawn()建立執行內建程式的新行程，附帶一條初始執行緒。
fork()建立子行程，準備獨立頁表與核心堆疊，複製返回使用者程式所需的暫存器。父收到子 PID，子收到 0。父子先共享常駐頁框，需要寫入時才拆分。繼承的 FD 指向相同的開啟檔案記錄，所以可能共用讀寫位置。
exec()／exec_argv()先準備新程式映像和堆疊，成功後才換掉原位址空間。沿用 PID 與 TID，從新程式入口繼續；準備失敗會回到原程式。
exit()／wait()exit() 開始整個行程的退出流程。核心清理其執行緒和資源，父行程可用 wait(pid, &status) 收取結果，或用 wait(-1, &status) 等任一子行程。沒有父行程的子行程由排程器安排回收。

kill(pid) 只接受符合條件的直接子行程，PID 1 受保護。fork() 和 exec() 要求目前行程只占用一格 TCB，尚未 join 的 Zombie 執行緒也算一格。使用外部 ELF 時，核心支援受限的靜態 RV64 映像與 exec_argv() 傳遞的引數。

一次 Shell 命令怎麼把三個操作串起來 ​

Shell 啟動外部程式時，fork() 讓子行程繼承準備好的資源，子行程可以先調整標準輸入、標準輸出，接著用 exec 換成目標程式。父行程視需要呼叫 wait 收回子行程的退出狀態。管線就是相同做法的延伸：Shell 先安排端點，再啟動各段，讓每個程式從自己的標準輸入與輸出讀寫。 Shell 執行路徑

執行緒如何建立和回收 ​

  • thread_create(entry, arg) 在同一行程內建立新的執行緒，成功回傳 TID。額外執行緒有自己的使用者堆疊與防護頁在堆疊旁保留且刻意不映射的一頁。當堆疊越界碰到它時，CPU 觸發例外，核心可以察覺越界存取。。
  • thread_exit(status) 結束呼叫者。入口函式直接回傳時，由啟動程式代為呼叫。最後一條執行緒退出時，行程也會進入退出流程。
  • thread_join(tid, &status) 等同一行程內的指定目標退出，收取結果並回收其 TCB 與額外堆疊。

系統上限為 16 個行程、32 格 TCB，每個行程最多占 8 格。既有 QEMU 案例涵蓋建立、阻塞 join、群組退出與 COW 隔離。 行程與執行緒生命週期 · Thread 規格 · ELF 規格 · Thread Stage A 驗收 · COW 驗收

I/O 等待 · A：RUNNING

A 準備讀取資料

A 呼叫 read，核心接手處理這次讀取，並使用 A 的核心堆疊保存函式資料。這次需要等裝置提供資料。

關鍵欄位
A.kernel_call_active = 1
原始碼：kernel/io/io.cSpec 34 · 狀態轉移與生命週期

I/O 等待 · A：WAITING

登記等待，A 讓出 CPU

核心記錄 A 在等哪一次裝置事件，把 A 標為等待中，並保留這次讀取的核心堆疊。

關鍵欄位
A.wait_reason = WAIT_EVENT；event_wait.active = 1
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

I/O 等待 · A：WAITING

A 等待期間，B 繼續前進

排程器選中 B。A 已離開就緒佇列，在裝置完成前不會占用 CPU 反覆檢查結果。

關鍵欄位
current = B；A.state = THREAD_WAITING
原始碼：kernel/proc/scheduler.cSpec 34 · 狀態轉移與生命週期

I/O 等待 · A：READY

事件完成，A 回到隊尾

核心可透過裝置中斷或主動檢查得知結果，接著把 A 排回就緒佇列。B 此時仍在執行。

關鍵欄位
A.event_wait.completed = 1；A.state = THREAD_READY
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

I/O 等待 · A：READY

B 讓出後，才輪到 A

B 呼叫 yield 主動讓出 CPU，排到 A 後面。A 現在位於隊首。

關鍵欄位
Ready queue = A → B
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

I/O 等待 · A：RUNNING

恢復 A 原本的 read 呼叫

排程器恢復 A 的核心堆疊，讓原本的 read 接著處理裝置回報的結果。核心完成後，A 回到使用者程式。

關鍵欄位
A.wait_reason = WAIT_NONE；原 kernel stack 繼續
原始碼：arch/riscv/swtch.SSpec 34 · 狀態轉移與生命週期

退出與回收 · A：RUNNING

同一 Process，兩條獨立 Thread

A 是額外建立的執行緒，有自己的 TCB、使用者堆疊和核心堆疊。它和 B 共用同一行程的記憶體映射與開啟檔案表。

關鍵欄位
A.process = B.process；A.tid ≠ B.tid
原始碼：kernel/proc/thread.hSpec 34 · 狀態轉移與生命週期

退出與回收 · A：ZOMBIE

A 結束，先保留 Zombie

A 的入口函式回傳 7，啟動用的組合語言程式接手呼叫 thread_exit。核心記下退出值，切回排程器，暫時保留 A 的 TCB 和堆疊。

關鍵欄位
A.exit_status = 7；A.state = THREAD_ZOMBIE
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

退出與回收 · A：ZOMBIE

B 繼續使用共享資源

B 接著執行，仍可使用行程的開啟檔案表與頁表。若呼叫的是行程的 exit，核心就會要求同一行程的所有執行緒結束。

關鍵欄位
Process.state = PROCESS_LIVE
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

退出與回收 · A：ZOMBIE

B 取得回收 A 的資格

B 呼叫 thread_join，核心先保留回收資格，避免兩條執行緒回收同一個目標。A 已經退出，核心可以開始把退出值寫回 B 提供的位置。

關鍵欄位
A.join_claimed = 1；A.joiner_tid = B.tid
原始碼：kernel/proc/process.cSpec 34 · 狀態轉移與生命週期

退出與回收 · A：UNUSED

A 的 TCB 回收，B 繼續執行

核心把 7 寫到 B 提供的變數，回收 A 的額外堆疊和 TCB，最後回傳 A 的 TID。B 現在可以讀取退出值。

關鍵欄位
A 的 TCB slot = THREAD_UNUSED；join status = 7
原始碼：kernel/proc/thread.cSpec 34 · 狀態轉移與生命週期
