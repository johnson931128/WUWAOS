WUWAOS 名詞表 ​

從正文點選名詞會跳到這裡。每個名詞有固定連結，方便在規格章節中引用同一份解釋。

QEMU ​

在主機上模擬另一台電腦的工具。WUWAOS 使用 QEMU 的 virt 機器來取得模擬的 RISC-V CPU、記憶體、UART 和磁碟裝置。

RISC-V 與 RV64 ​

RISC-V 是 CPU 指令和執行環境的規格。RV64 表示採用 64 位元的 RISC-V 基礎架構。WUWAOS 的核心和使用者程式由主機工具編譯成這套指令。

WSL ​

Windows 上的 Linux 執行環境。WUWAOS 的原始碼可以在 WSL 內的 Ubuntu 用 Linux 工具建置，再由 QEMU 執行編出的 RISC-V 系統。

Flash 載入器 ​

以 QEMU 模擬 Flash 作為來源的小型開機程式。WUWAOS 的磁碟開機路徑由它讀取 WUFS 內的 /boot/kernel.elf，把控制權交給核心。

UART ​

傳送和接收序列資料的裝置。WUWAOS 的 CLI 使用 QEMU 提供的 UART 收鍵盤輸入、送出終端文字。

ELF ​

可執行檔與程式資料的容器格式。WUWAOS 的 ELF 載入器讀取檔案中描述位址、大小和權限的資料，建立新程式映像。可執行的使用者程式還要符合 WUWAOS 的系統呼叫約定。

OpenSBI ​

RISC-V 的開機韌體。它先在比核心權限更高的 M-mode 啟動，交出控制權後仍可透過 Supervisor Binary Interface（SBI）提供計時器與跨 Hart 等服務。

Hart ​

硬體可獨立執行指令的一個位置，具有自己的暫存器和指令位置。QEMU 設定 -smp 2 時，WUWAOS 可在兩個 Hart 上各派一條執行緒。

U-mode 與 S-mode ​

RISC-V 的權限層級。U-mode 跑使用者程式，只能依核心設定存取資源。WUWAOS 核心跑在 S-mode，負責頁表、陷阱和硬體服務。

系統呼叫（System Call） ​

使用者程式請核心代辦工作的介面。例如 read() 透過 ecall 把編號和參數交給核心，完成後取得讀了幾個 bytes 或錯誤碼。

陷阱（Trap） ​

CPU 暫停目前指令流程，跳到核心的事件處理入口。原因可能是程式主動呼叫核心、執行指令時遇到例外，或硬體發出的計時器／裝置中斷。

TrapFrame ​

陷阱發生時由核心保存的一組暫存器與返回位置。核心返回使用者模式之前，會依它還原需要的狀態。

行程（Process） ​

一份正在運作的程式及其資源。行程用 PID 辨認，持有自己的位址空間、檔案描述符和工作目錄，可以包含多條執行緒。

執行緒（Thread） ​

在 CPU 上前進的一條指令流程，用 TID 辨認。同一行程內的執行緒共用記憶體，各有自己的堆疊與暫存器狀態。

行程控制區塊（PCB） ​

核心為每個行程保存的記錄，包含 PID、父 PID、頁表位置、檔案描述符、工作目錄和退出狀態。

執行緒控制區塊（TCB） ​

核心為每條執行緒保存的記錄，包含 TID、所屬行程、執行狀態、等待原因、堆疊及切換時要保存的狀態。

防護頁（Guard Page） ​

在堆疊旁保留且刻意不映射的一頁。當堆疊越界碰到它時，CPU 觸發例外，核心可以察覺越界存取。

就緒佇列（Ready Queue） ​

存放可以執行、正在等 CPU 的執行緒。WUWAOS 從隊首派發，也把剛就緒或讓出 CPU 的執行緒放到隊尾。

輪流排程（Round-robin，RR） ​

讓已就緒的執行緒輪流使用 CPU。WUWAOS 每次派發設定 50 ms 時間片，執行緒也可能提前阻塞、退出或主動讓出 CPU。

FIFO ​

先進先出。用於就緒佇列時，通常先派發排在最前面的執行緒；用於分頁置換時，先找最早入駐且允許換出的頁框。

核心上下文（Kernel Context） ​

核心在切換執行緒時保存的堆疊指標、返回位置與必要暫存器。這讓暫停的核心函式可以在原本的呼叫位置繼續執行。

競爭條件（Race Condition） ​

程式結果取決於執行緒恰好如何交錯。例如兩條執行緒同時替計數器加一，若各自讀到相同舊值，其中一次寫入可能蓋掉另一次。

臨界區（Critical Section） ​

存取共用資源時需要保持完整的一段操作。例如更新佇列時，寫入資料和移動指標應合在一次受保護的操作中。

互斥鎖（Mutex） ​

有一位擁有者的鎖，用來保護臨界區。持有者完成後才能解鎖。WUWAOS 用執行緒身分判斷誰有權解鎖。

號誌（Semaphore） ​

記錄可用份數的同步物件。等到一份資源時減一，歸還或生產資源時加一。即使當下沒有等待者，已增加的份數也會保留。

KernelGate ​

核心內部用來保護操作邊界的鎖。擁有者可以配對地重複進入和離開，其他執行緒會等待或在不能睡眠的路徑收到忙碌結果。

核心事件來源（Kernel Event Source） ​

核心用來通知等待者的物件。Generation 區分同一欄位的不同使用週期，sequence 表示通知有沒有更新。等待可以帶期限，結果留給被喚醒的執行緒收取。

檔案描述符（File Descriptor，FD） ​

使用者程式用來讀、寫或關閉某個 I/O 來源的整數。相同數字在不同的行程內可以指到不同物件。

開啟檔案記錄（Open File Description，OFD） ​

核心保存一次開啟操作的記錄，包含來源、讀寫位置與引用。多個 FD 可指到同一筆記錄，因此共用位置。

TTY ​

核心管理的終端輸入輸出端點。WUWAOS 可把 Shell 接到 UART，也可接到圖形桌面上的 Terminal。

VirtIO ​

虛擬機與模擬裝置交換請求的介面。WUWAOS 的磁碟驅動把操作放進 VirtIO 佇列，裝置完成後回報結果。

PLIC ​

平台層級中斷控制器。裝置送出外部中斷後，核心透過它辨識是哪個來源，再交給相應的處理函式。

輪詢（Polling） ​

由程式主動檢查「完成了嗎」，例如在開機時重複讀取磁碟狀態。中斷是裝置主動通知核心，兩條路徑可以共用完成檢查。

磁區（Sector） ​

磁碟讀寫的編號單位。WUWAOS 的 WUFS 和 Swap 使用 512 bytes 磁區，一個 4 KiB 的 Swap 槽位占八個磁區。

虛擬位址（Virtual Address） ​

程式拿來存取記憶體的位址。CPU 依目前的頁表把它換成實體位址。同一個虛擬位址在不同行程可以對應到不同頁框。

頁面與頁框（Page、Frame） ​

頁面是虛擬位址空間的一段，頁框是 RAM 裡能放下一頁的實體空間。WUWAOS 兩者都使用 4 KiB 單位。

Heap ​

程式在執行時可取得更多儲存空間的一段虛擬位址範圍。WUWAOS 用 sbrk() 調整這段範圍的結尾，在首次存取時才準備對應頁框。

Sv39 ​

RISC-V 的一種虛擬記憶體轉譯方式。WUWAOS 依虛擬位址逐層查三層頁表，最後取得頁框與存取權限。

頁表項目（Page Table Entry，PTE） ​

頁表裡的一筆資料，可以指向下一層頁表或一個頁框。指向頁框時也記錄讀、寫、執行等權限。

轉譯快取（TLB） ​

CPU 暫存最近查過的虛擬位址轉譯。核心更改映射或權限時會同步 TLB，避免 CPU 繼續使用舊的頁框位置或寫權限。

缺頁（Page Fault） ​

CPU 發現某次存取沒有可用映射或權限不符而進入核心。合法的按需載入和 COW 都可能帶來缺頁，核心會再判斷能否繼續。

乾淨頁與修改頁（Clean、Dirty） ​

乾淨頁仍可由原映像、零值或有效的 Swap 副本重建。修改頁包含必須保留的新內容，需要寫出才能安全回收它的頁框。

交換區（Swap） ​

用磁碟保存暫時離開 RAM 的頁面。程式再次存取該頁時，核心從指定槽位讀回內容並重建映射。

寫入時複製（Copy-on-Write，COW） ​

父子行程先共享同一個頁框。原本可寫的頁先關閉寫權限，讓第一次寫入進核心處理。核心只在還有其他引用時複製原頁，最後一個擁有者可以在原頁框上恢復寫權限。

Inode ​

檔案系統存放物件資訊的記錄，可包含種類、長度與資料磁區位置。目錄中的名字會指到 inode，開啟中的檔案也可持有它。

WUFS ​

WUWAOS 自有的磁碟檔案系統。它把路徑和檔案內容對應到磁碟中的目錄、inode 與磁區。各版本的差異見檔案系統規格。

硬連結（Hard Link） ​

讓兩個目錄名稱指到同一個 inode。從任一名稱讀取都會取得同一份檔案內容，刪除其中一個名稱仍保留其他可用名稱。

重做日誌（Redo Journal） ​

先存一筆交易要寫入的新磁區內容，再標記交易已提交，然後才改動正式位置。若在改動途中中斷，下次掛載可按已提交的資料重做。

Flush ​

請存放裝置把已接收的寫入推到可持久保存的位置。WUFS 在交易的關鍵步驟等待 flush 成功，避免下一步超前於應該先完成的磁碟寫入。
