Spec 09：fan 終端文字編輯器 ​

目標與範圍 ​

在 QEMU 序列埠終端直接執行 fan /absolute/path，提供類似 nano 的單一編輯模式 TUI。程式以 C 撰寫、在獨立 U-mode 子行程執行；不使用網頁或主機代編輯檔案。不新增測試程式碼，不自行 commit／push。

使用方式與驗收條件 ​

  • 支援 ASCII 可列印字元、LF 換行、既有 Tab；最多 2048 bytes。開檔多讀一個 byte 偵測超限；含其他位元組（包括 UTF-8、CR、NUL、ESC）的檔案拒絕開啟，不寫回。
  • 尚不存在的檔案以空緩衝區開啟，第一次成功儲存才建立；沒有父目錄時儲存回報錯誤且保留緩衝區。
  • 方向鍵移動、Home／End 到行首／行尾、Backspace／Delete 刪除、Enter 插入 LF，Tab 插入至下一個四欄位置所需的空白。既有 Tab 以 > 顯示並視為一欄，儲存時仍保留原 Tab。
  • Ctrl+O 儲存；Ctrl+X 離開。有修改時選 y 儲存後離開／n 捨棄／c 或 Escape 取消；儲存失敗留在編輯器。Ctrl+L 重畫。
  • ANSI 終端至少 80×24；固定 78 欄、20 行編輯區，提供垂直／水平捲動、檔名、修改標記、游標行列、訊息列與快捷鍵提示。未做視窗大小偵測、語法上色、搜尋、undo、滑鼠或 Vim 命令模式。

架構與演算法 ​

  • user/fan.c 另行連結成 fan.elf／fan.bin，使用既有 16 KiB code、4 KiB data 與 4 KiB stack 布局，核心嵌入第三份映像；仍不是磁碟 ELF loader。
  • shell fork 後，子行程以擴充 exec 呼叫傳入 PROGRAM_FAN 及路徑；核心在替換前驗證／複製舊使用者路徑，將它放到新使用者堆疊頂端，a1 傳其位址，sp 調整至字串下方。既有 exec(program) 維持可用。
  • 新增 console_mode(raw) 系統呼叫，raw 模式提供不回顯、逐 byte 的阻塞讀取。單一行程持有 raw console，其他讀取者拒絕；exit／kill／成功 exec 釋放持有者。shell 等待編輯器期間不讀輸入，返回時恢復終端顏色、游標與一般畫面。
  • 編輯緩衝區為固定長度連續 byte 陣列，游標為 byte offset。插入／刪除以搬移後段實作，O(N)；行首／行尾／上下移動掃描文字，不使用 heap。上／下移動保留目標欄位。
  • Escape 序列用有限狀態解碼，不等待完整序列的同步迴圈；支援 CSI／SS3 方向鍵及常用 Home／End／Delete／PageUp／PageDown 序列，未知序列忽略。
  • 每個編輯動作後計算可見範圍，以逐行內容快取只重畫有改變的行；Ctrl+L 清除快取並完整重畫。控制字元不直接輸出成檔案內容，避免檔案中的終端控制碼被執行。
  • fan 的逐鍵等待狀態仍更新真實 PCB，但省略該行程的 transition 追蹤文字，避免每次按鍵破壞畫面。其他背景行程的輸出仍可能交錯，尚無完整前景工作與終端輸出隔離。
  • 儲存沿用 WUFS 整檔覆寫，不提供原子儲存／掉電交易保護。成功寫入完整長度才清除 dirty（未儲存修改）標記。

執行步驟 ​

  1. 加入 raw console 輸入與持有者清理，保留 shell 行輸入及 pipe。
  2. 加入 fan 映像、exec 路徑傳遞與 shell 前景等待。
  3. 實作文字編輯、按鍵解碼、捲動、儲存與退出確認。
  4. 編譯；在獨立磁碟映像的 QEMU 互動驗證建立／重開／修改／捨棄／取消、儲存失敗、拒絕不支援檔案，以及既有 shell／process／pipe 行為。
  5. 重啟讀回檔案、觀察頁數回到基準，更新 CODE_GUIDE 與 README。

引用來源 ​

  • notes/ch12 I_O Systems.md：終端與裝置 I/O 的分層觀念；WUWAOS 目前採 UART 輪詢，raw console 是自訂介面，並非完整 POSIX termios。
  • XTerm Control Sequences：游標定位、清行、反白、替代畫面與按鍵序列。

驗收紀錄 ​

2026-10-26，WSL Ubuntu／Clang 18／QEMU 8.2.2／OpenSBI 1.3，virt／單 hart／128 MiB。以 QEMU 序列終端、一般 shell 命令與鍵盤輸入驗收，沒有新增測試程式碼。

  • make clean && make 通過 -Wall -Wextra -Werror；kernel.elf／user.elf／app.elf／fan.elf 的 llvm-nm -u 無未解析符號。fan.elf 的 text=7752、data=8、bss=3888 bytes，通過既有 16 KiB code／4 KiB data linker 限制。git diff --check 通過。
  • 初輪在 trace on 下啟動 fan，fork／exec 後畫面顯示檔名、修改標記、20 行編輯區、行列位置及快捷鍵；逐字元讀取不需要 Enter、不額外回顯，fan 狀態追蹤不插入畫面。
  • 建立 /home/user/note.txt，透過 Enter、Tab、Backspace、Delete、上下方向鍵與 Home／End 修改，Ctrl+O 後 cat 讀回 fan: Hello WUWAOS、Second line!、四個空白加 four spaces 三行。退出自動 wait，空閒頁回基準。
  • 分別按鍵確認 Ctrl+X 後 c／Escape 取消、n 捨棄、y 儲存後離開。最終版重新開啟 /home/user/fan.txt，插入驚嘆號後 c 取消退出，再 n 捨棄；cat 確認磁碟內容未變。以 CRLF 結尾輸入 fan 命令，開檔後仍從 Ln 1 Col 1 開始，命令的 LF 沒有插入檔案。
  • /missing/path.txt 的父目錄不存在：Ctrl+O 與 Ctrl+X→y 均顯示 Save failed; buffer kept -2 並留在原緩衝區，最後可捨棄離開。編輯目錄回 -21、相對路徑由 shell 拒絕，shell 之後仍接受行輸入。
  • 初輪輸入 90 字元長行與 26 行內容，畫面水平／垂直捲動；PageUp／PageDown 可移動。輸入 2048 個 x 後再輸入 X，仍顯示 2048/2048 與 Buffer full；儲存後重啟最終版，重新開啟確認 2048 bytes，End 定位 Col 2049，再輸入 X 被拒絕且不標 dirty。
  • 大型 /boot/kernel.elf 被拒絕為超過 2048 bytes。為驗證不支援編碼，停機後以既有 make_disk.py 將 AGENTS.md（1060 bytes，含 UTF-8 中文）放入獨立驗證磁碟的 kernel 副本位置；執行中的核心仍由 QEMU -kernel 載入。fan 拒絕該內容、不寫回。後續已用正常 kernel.elf 還原此磁碟副本。
  • 最終版 /home/user/fan.txt 儲存三行、57 bytes（含空白與 LF）；關閉 QEMU、完整重編譯並更新磁碟核心副本後重啟，cat 讀回相同內容。再次 fan 加入 fan> 前綴，以 Ctrl+X→y 儲存離開，cat 讀回 62 bytes。可儲存空檔 /home/user/empty.txt，cat 直接返回提示。
  • 修改重畫方式後，最終版確認訊息列與文字行只在內容改變時更新，方向鍵可移動游標；前後重開編輯器皆能正常工作。未逐一驗證所有主機終端或動態縮放，不宣稱 Windows 原生獨立視窗的畫面驗收。
  • 新版一般 fork／wait 父子資料隔離正常，run quick／wait 回 40，固定 writer | reader 傳完 80 bytes／EOF 並回收。各次編輯器與工作程式退出後 ps 只剩 shell、三個空閒 PCB，free=31499／total=31576；數值隨核心大小可能改變。
  • 僅使用獨立 build/fan-check.img，未修改原有 build/wuwaos.img。本機互動記錄為忽略的 build/fan-console.log、build/fan-final-console.log、build/fan-reboot-console.log。

尚未動態驗證：raw console 多行程競爭 -16、持有 raw console 時遭 kill／使用者例外的恢復、錯誤 exec 使用者指標、裝置錯誤與記憶體耗盡。相關清理已靜態檢查；第一版仍沒有完整前景工作隔離、Unicode、undo 或原子儲存。
