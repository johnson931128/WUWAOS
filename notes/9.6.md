前面 PAE 那段確實講太繞，重來一次。這次把 **9.6.1 IA-32 Architecture** 從頭整理成一條乾淨的主線。

IA-32 的重點不是單純「logical address 直接 paging 成 physical address」，而是分成兩段：

```txt id="hzx6f4"
CPU 產生 logical address
        ↓
Segmentation unit
        ↓
32-bit linear address
        ↓
Paging unit
        ↓
physical address
        ↓
physical memory
```

也就是課本 Figure 9.21 的意思：**segmentation unit 先把 logical address 轉成 linear address，paging unit 再把 linear address 轉成 physical address**。課本也明確說 segmentation unit 和 paging unit 合起來，就等同於這個架構中的 MMU。

---

## 1. IA-32 Architecture 整體概念
![image](https://hackmd.io/_uploads/HJLWIpQfMl.png)
IA-32 是 Intel 32-bit 架構。它的記憶體管理分成兩個機制：

```txt id="xkt7xm"
1. Segmentation
   負責：logical address → linear address

2. Paging
   負責：linear address → physical address
```

所以這裡會出現三種 address：

```txt id="iwzcft"
logical address：
CPU / 程式產生的位址，格式是 selector + offset

linear address：
segmentation 處理完後產生的 32-bit 位址

physical address：
paging 處理完後，真正送去 RAM 的位址
```

最容易混淆的就是 **linear address 還不是 physical address**。它只是 paging unit 的輸入。

---

## 2. IA-32 Segmentation：先處理 selector + offset
![image](https://hackmd.io/_uploads/BkPz8a7zzx.png)
IA-32 的 logical address 長這樣：

```txt id="rj0ovl"
logical address = (selector, offset)
```

其中：

```txt id="dfsq1f"
selector = 16 bits
offset   = 32 bits
```

selector 又被拆成三個部分：

```txt id="pe4oc3"
| s 13 bits | g 1 bit | p 2 bits |
```

`s` 是 segment number，也就是要查 descriptor table 的第幾個 segment descriptor。13 bits 可以表示：

```txt id="aqb1n9"
2^13 = 8192 = 8K
```

所以一張 descriptor table 最多可以有 8K 個 segment entries。

`g` 是用來決定查哪一張表。IA-32 有兩種 descriptor table：

```txt id="zvqy0v"
LDT = Local Descriptor Table
     存放該 process 私有的 segment

GDT = Global Descriptor Table
     存放所有 processes 共享的 segment
```

課本說 IA-32 每個 process 最多可以有 16K 個 segments，其中最多 8K 個 private segments 放在 LDT，最多 8K 個 shared segments 放在 GDT。每個 LDT / GDT entry 是 8-byte segment descriptor，裡面包含該 segment 的 base location 和 limit。

`p` 跟 protection 有關，也就是權限檢查，例如目前執行狀態是否有資格存取這個 segment。

---

## 3. Segment descriptor 到底存什麼？

Segment descriptor 可以先理解成一筆「segment 的資料卡」。最重要的是兩個欄位：

```txt id="6zt1el"
base  = 這個 segment 的起始位置
limit = 這個 segment 的大小 / 邊界
```

segmentation unit 做的事就是：

```txt id="t9bg9x"
selector → 找到 segment descriptor
        → 取得 base 和 limit
        → 檢查 offset 有沒有超過 limit
        → 沒超過：linear address = base + offset
        → 超過：memory fault / trap
```

課本說 IA-32 的 linear address 是 32 bits。產生 linear address 前，硬體會先用 limit 檢查 address validity；如果不合法，會產生 memory fault 並 trap 到 OS；如果合法，才會把 offset 加到 base，得到 32-bit linear address。

---

## 4. Segmentation 例子

假設某個 logical address 是：

```txt id="birhoq"
selector = 指到某個 segment descriptor
offset   = 0x0000302A
```

而 descriptor table 查到這個 segment descriptor：

```txt id="18srsv"
base  = 0x00400000
limit = 0x00100000
```

先檢查 offset：

```txt id="94o8a4"
0x0000302A < 0x00100000
```

合法，所以：

```txt id="qso95v"
linear address = base + offset
               = 0x00400000 + 0x0000302A
               = 0x0040302A
```

到這裡只完成第一段：

```txt id="wvw771"
logical address → linear address
```

接下來才進入 paging。

---

## 5. IA-32 Paging：把 linear address 轉 physical address
![image](https://hackmd.io/_uploads/H1NELTmffg.png)
IA-32 支援兩種 page size：

```txt id="xez21j"
4 KB page
4 MB page
```

先看標準的 **4 KB page**。

因為：

```txt id="3k7x6c"
4 KB = 4096 bytes = 2^12 bytes
```

所以 page offset 需要 12 bits。

而 IA-32 linear address 是 32 bits，所以剩下：

```txt id="f1w0m7"
32 - 12 = 20 bits
```

這 20 bits 被拆成兩個 10 bits：

```txt id="r0y9a7"
32-bit linear address：

| p1 10 bits | p2 10 bits | d 12 bits |
```

也就是：

```txt id="gtxdzi"
p1：page directory index
p2：page table index
d ：page offset
```

課本說，IA-32 在 4-KB pages 下使用 two-level paging：高 10 bits 用來 reference page directory entry；CR3 register 指向目前 process 的 page directory；page directory entry 再指向 inner page table；中間 10 bits 用來 index page table；低 12 bits 是 4-KB page 內部 offset。

---

## 6. p1、p2、entry 的關係

這裡要講清楚。

```txt id="2r2gyw"
p1 不是 entry
p1 是 index

p2 也不是 entry
p2 也是 index

entry 是表格裡面被 index 選到的那一格資料
```

一般 IA-32 的 page directory / page table 都是一張 4 KB 的表。每個 entry 是 32 bits，也就是 4 bytes。

所以一張表可以放：

```txt id="jx3m32"
4096 bytes / 4 bytes = 1024 entries
```

而：

```txt id="tlnfn0"
1024 = 2^10
```

所以剛好需要 10 bits 來選其中一個 entry。

也就是：

```txt id="3sk6js"
p1 有 10 bits
→ 可以表示 0 ~ 1023
→ 用來選 page directory 裡的 1024 個 entries 其中一個

p2 有 10 bits
→ 可以表示 0 ~ 1023
→ 用來選 page table 裡的 1024 個 entries 其中一個
```

所以圖上的 `10 | 10 | 12` 其實是在說：

```txt id="3hd8xk"
第一個 10 bits：選 page directory 的一格
第二個 10 bits：選 page table 的一格
最後 12 bits：選 page 裡面的某個 byte
```

---

## 7. 4 KB paging 完整流程

假設 segmentation 後得到：

```txt id="8jp9zm"
linear address = 0x0040302A
```

它被拆成：

```txt id="d09hlx"
p1 = 1
p2 = 3
d  = 0x02A
```

假設 CR3 指向目前 process 的 page directory。

流程如下：

```txt id="ctwfw2"
Step 1:
用 p1 = 1 查 page directory[1]

page_directory[1]
→ 這個 entry 裡面記錄某張 page table 的位置

Step 2:
用 p2 = 3 查那張 page table[3]

page_table[3]
→ 這個 entry 裡面記錄某個 physical frame number

Step 3:
用 d = 0x02A 當作 frame 內部 offset

physical address = physical frame base + d
```

假設 `page_table[3]` 查到：

```txt id="0xvxcc"
physical frame number = 0x000AB
```

因為 page size 是 4 KB：

```txt id="lyu9zg"
frame base = 0x000AB × 0x1000
           = 0x000AB000
```

最後：

```txt id="tm9zhq"
physical address = 0x000AB000 + 0x02A
                 = 0x000AB02A
```

這就是 `linear address → physical address`。

---

## 8. 4 MB page：跳過 page table

IA-32 也支援 4 MB page。這時候不用第二層 page table。

4 MB 是：

```txt id="h4hro2"
4 MB = 2^22 bytes
```

所以 offset 需要 22 bits。

格式變成：

```txt id="ezfk6e"
32-bit linear address：

| page directory 10 bits | offset 22 bits |
```

如果 page directory entry 裡面的 **Page Size flag** 被設定，代表這個 entry 不是指向 page table，而是直接指向一個 4-MB page frame。課本說 Page Size flag 若被設定，page directory 會直接指向 4-MB page frame，跳過 inner page table，而 linear address 的低 22 bits 會作為 4-MB page frame 內部 offset。

所以：

```txt id="nzxyfd"
4 KB page：
CR3 → page directory → page table → 4-KB page

4 MB page：
CR3 → page directory → 4-MB page
```

好處是少查一層，TLB coverage 也比較大。缺點是 page 太大，容易浪費記憶體，也就是 internal fragmentation 可能比較嚴重。

---

## 9. Page table 本身也可以被換到 disk

這段也很重要。IA-32 不只 data page 可以被 swap out，連 page table 本身也可以被 swap 到 disk。

原因是：每個 process 都可能有很大的 address space，如果每個 process 的所有 page tables 都常駐 RAM，會浪費很多 physical memory。

課本說 IA-32 page tables 可以被 swapped to disk；page directory entry 裡面可用 invalid bit 表示它指向的 table 在 memory 還是 disk。如果 table 在 disk，OS 可以用其他 31 bits 記錄 disk location，需要時再把 table 載回 memory。

所以可能發生兩種 fault：

```txt id="08dgl0"
情況 A：
page table 在 RAM，但 data page 不在 RAM
→ page fault 後載入 data page

情況 B：
連 page table 本身都不在 RAM
→ 先把 page table 從 disk 載回來，再繼續查表
```

## 10. PAE：Page Address Extension
![image](https://hackmd.io/_uploads/rkyPLT7MMl.png)
PAE 的目的：**讓 32-bit processor 可以存取超過 4 GB 的 physical memory。**

傳統 IA-32 的限制是：

```txt id="zej9yx"
physical address = 32 bits
最大 physical memory = 2^32 bytes = 4 GB
```

但後來程式與系統需要更多 RAM，所以 Intel 設計 PAE。課本說 PAE 讓 32-bit processors 可以 access physical address space larger than 4 GB，並且 paging 從 two-level scheme 變成 three-level scheme。

PAE 的位址切法是：

```txt id="9zfuqq"
32-bit linear address：

| 2 bits | 9 bits | 9 bits | 12 bits |
| PDPT   | PD      | PT      | offset  |
```

流程變成：

```txt id="t7ycz1"
CR3
 ↓
Page Directory Pointer Table
 ↓
Page Directory
 ↓
Page Table
 ↓
4-KB page
```

也就是 Figure 9.24 的圖。

---

## 11. PAE 為什麼是 2 + 9 + 9 + 12？

先看最後的 12 bits：

```txt id="wg4zrn"
4 KB page = 2^12 bytes
所以 offset = 12 bits
```

這個沒變。

PAE 中，page-directory entry 和 page-table entry 從 32 bits 變成 64 bits。課本明確說，PAE increased the page-directory and page-table entries from 32 to 64 bits。

一張 page directory / page table 還是 4 KB：

```txt id="i06fus"
4 KB = 4096 bytes
```

但每個 entry 變成：

```txt id="i50e9a"
64 bits = 8 bytes
```

所以一張表只能放：

```txt id="8auy4m"
4096 / 8 = 512 entries
```

而：

```txt id="0iihh3"
512 = 2^9
```

所以 page directory index 和 page table index 都變成 9 bits。

最上面的 PDPT 只有 4 個 entries：

```txt id="c1z0t5"
4 = 2^2
```

所以最高位元用 2 bits 來選 PDPT entry。

因此 PAE 才是：

```txt id="htguza"
2 + 9 + 9 + 12 = 32 bits
```

注意：**linear address 還是 32 bits，沒有變大。**

---

## 12. 這次把 PAE 的 24 和 36 講清楚

這邊前面卡住的地方，因果要正確。

PAE 不是先天「因為 36 所以 24」。正確順序是：

```txt id="fi8uzl"
PAE 把 PDE/PTE 從 32 bits 擴成 64 bits
        ↓
entry 裡面可以放更長的 physical frame base address
        ↓
課本說 base address of page tables and page frames 從 20 bits 擴成 24 bits
        ↓
4 KB page 的 offset 固定是 12 bits
        ↓
physical address = 24-bit frame base/index 部分 + 12-bit offset
                 = 36 bits
```

課本原文的邏輯就是：PAE 將 page-directory / page-table entries 從 32 bits 增加到 64 bits，這讓 page tables 與 page frames 的 base address 從 20 bits 延伸到 24 bits；再配合 12-bit offset，IA-32 的 address space 增加到 36 bits，可支援最多 64 GB physical memory。

所以這裡要記：

```txt id="7y0xrp"
24 bits：
來自 PAE entry 格式可以記錄更長的 page frame base address

36 bits：
24-bit frame/base 部分 + 12-bit offset 的結果
```

PAE 的重點不是讓 process 看到更大的 virtual address。單一 32-bit process 的 linear address 仍是 32 bits，也就是最多 4 GB virtual address space。PAE 擴大的是 **physical address ability**，也就是整台機器能用更多 RAM。

---

## 13. 9.6.1 最終總結

IA-32 位址轉換整體如下：

```txt id="y1u9oa"
logical address = selector + offset

selector
→ 決定查 LDT 或 GDT
→ 找到 segment descriptor
→ descriptor 裡有 base 和 limit
→ 檢查 offset 是否超過 limit
→ 合法則 linear address = base + offset

linear address
→ 交給 paging unit

4 KB paging：
linear address = p1 + p2 + d
p1 查 page directory
p2 查 page table
d 是 4-KB page 內 offset

4 MB paging：
page directory entry 直接指向 4-MB page
低 22 bits 當 offset

PAE：
linear address 仍然 32 bits
切成 2 + 9 + 9 + 12
多一層 page directory pointer table
PDE/PTE 從 32 bits 變 64 bits
frame/base address 欄位從 20 bits 擴成 24 bits
physical address 變成 36 bits
最多支援 64 GB physical memory
```

最核心的一句話是：

**IA-32 的記憶體管理是「先 segmentation，後 paging」。Segmentation 負責把 `(selector, offset)` 變成 32-bit linear address；paging 再把這個 linear address 變成真正的 physical address。PAE 則是在 paging 架構中加一層表，並把 entries 變大，讓 32-bit 系統可以指到超過 4 GB 的實體記憶體。**
