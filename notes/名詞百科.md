# ch6

### 一、 核心概念與併發問題 (Core Concepts & Problems)

* **Concurrent execution**：並發執行
* **Parallel execution**：平行執行
* **Race Condition**：競態條件（多個實體同時存取共享資料，結果取決於執行的特定順序）
* **Context Switch**：內容交換
* **Instruction Reordering**：指令重排（現代硬體或編譯器為求效能而調換指令順序）
* **Deadlock**：死結（多個行程互相等待對方釋放資源，導致全體卡死）
* **Starvation**：飢餓（行程被無限期推遲，永遠拿不到資源）
* **Busy waiting**：忙碌等待（拿不到鎖時在 `while` 迴圈中不斷空轉浪費 CPU）
* **Lock Contention**：鎖競爭（包含 High contention 高競爭與 Low contention 低競爭）

### 二、 臨界區間與三大鐵律 (Critical-Section & The Three Requirements)

* **Critical Section**：臨界區間（存取共享資料的危險程式碼區塊）
* **Entry section / Exit section**：進入區間（申請鎖）/ 離開區間（釋放鎖）
* **Remainder section**：剩餘區間（與共享資料無關的其他程式碼）
* **Mutual exclusion**：互斥（同一時間只能有一個行程進入臨界區間）
* **Progress**：進行（不想進去的人不能卡住想進去的人，避免死結）
* **Bounded waiting**：有限等待（排隊有上限，避免飢餓）

### 三、 硬體層級同步支援 (Hardware Support)

* **Memory Model**：記憶體模型（包含 Strongly ordered 強排序與 Weakly ordered 弱排序）
* **Memory Barriers / Memory Fences**：記憶體屏障 / 記憶體柵欄（防止指令重排的底層硬體指令）
* **Atomic Operations**：原子操作（不可分割、一氣呵成的硬體執行單元）
* **`test_and_set`**：測試與設定指令（硬體原子指令）
* **`compare_and_swap` (CAS)**：比較與交換指令（硬體原子指令）
* **Atomic Variables**：原子變數（如 `atomic_int`，利用 CAS 實作的單一變數更新工具）
* **Optimistic Locking**：樂觀鎖（先運算再用 CAS 檢查有無衝突的無鎖設計）

### 四、 軟體高階同步工具 (Software Synchronization Tools)

* **Mutex Lock**：互斥鎖（Mutual exclusion 的縮寫）
    * **acquire()：取得**
    * **release()：釋放**
* **Spinlock**：自旋鎖（會產生忙碌等待的互斥鎖，適用於短暫時間的防護）
* **Semaphore**：號誌（包含 wait/P 操作與 signal/V 操作）
    * `wait()` (或稱 P 操作)：用來申請資源。它會先將號誌的資源數值減 1。如果減完後數值小於 0，代表資源已耗盡，該行程會立刻將自己加入等待名單，並呼叫 `sleep()` 強制休眠交出 CPU。
    * `signal()` (或稱 V 操作)：用來釋放/歸還資源。它會將號誌的資源數值加 1。如果加完後數值依然小於等於 0，代表外面還有行程在苦苦排隊，系統會從等待名單中挑選一個幸運兒，並呼叫 `wakeup()` 將其喚醒準備執行。
* **Binary Semaphores**：二元號誌（值為 0 或 1，常做為互斥鎖使用）
* **Counting Semaphores**：計數號誌（管控有限數量的實體資源）
* **Monitor type**：管程型別（將共享資料與同步機制封裝在一起的抽象資料型別 ADT）
* **Condition Variables**：條件變數（供行程在管程內暫時休眠退位的機制）
* **Signal and wait / Signal and continue**：管程中喚醒休眠行程後的兩種控制權移交流派



### 五、 經典同步問題 (Classic Problems of Synchronization)

* **The Bounded-Buffer Problem**：有限緩衝區問題（即生產者－消費者問題 Producer-Consumer Problem）
    * 探討生產者與消費者共享一個固定大小緩衝區的同步情境；其核心在於利用號誌控管資源與互斥，確保生產者在緩衝區「客滿」時必定休眠等待、消費者在緩衝區「空虛」時暫停讀取，並嚴格保證任何時刻都只能有一個行程對緩衝區進行寫入或取出，以防資料互相覆蓋或讀取異常。
* **The Readers–Writers Problem**：讀者－寫者問題（衍生出 Reader-Writer Locks 讀寫鎖）
    * 模擬多個行程並發存取共享資料庫的衝突與效能取捨；其核心防護原則是允許多個「讀者 (Readers)」同時讀取資料以最大化系統效能，但嚴格規定「寫者 (Writers)」在修改資料時必須擁有絕對的排他獨佔權 (Exclusive access)，禁止任何其他讀者或寫者同時闖入，藉此避免資料庫陷入混亂狀態。
* **The Dining-Philosophers Problem**：哲學家就餐問題（探討資源分配與死結、循環等待 Circular Wait）
# ch8
### 一、 核心名詞與物理模型 (Core Terms & System Model)

* **Resource types**：資源類型（如 CPU、檔案、I/O 裝置、甚至是互斥鎖與號誌，皆被視為系統資源）
* **Identical instances**：相同的實例（同一資源類型下可互相替代的資源個體）
* **Request / Use / Release**：資源操作標準程序（申請、使用、釋放）
* **Resource-Allocation Graph**：資源分配圖（由執行緒頂點與資源頂點構成的視覺化圖形）
* **Request Edge**：申請邊（執行緒指向資源，代表等待中）
* **Assignment Edge**：分配邊（資源黑點指向執行緒，代表已握有該實例）

### 二、 死結特徵與四大必要條件 (Deadlock Characteristics)

* **Deadlock**：死結（一組執行緒皆在等待同集合內其他執行緒才能觸發的釋放事件，導致系統卡死）
* **Mutual Exclusion**：互斥（資源具排他性，不可共享）
* **Hold and Wait**：持有並等待（執行緒握有部分資源，同時等待獲取別人手上的資源）
* **No Preemption**：不可剝奪（系統不可強行搶奪資源，需等執行緒自願釋放）
* **Circular Wait**：循環等待（形成完美的封閉等待環）

### 三、 死結處理四大流派 (Four Major Handling Strategies)

* **Deadlock Prevention**：死結預防（從物理或邏輯上制定嚴格規範，破壞四大必要條件之一，確保死結永不發生）
* **Deadlock Avoidance**：死結避免（要求執行緒預先宣告最大需求，每次分配前進行沙盤推演，避免進入不安全狀態）
* **Deadlock Detection**：死結偵測（允許死結發生，定期在背景尋找循環等待的證據）
* **Recovery from Deadlock**：死結復原（抓到死結後，透過殺死行程或剝奪資源來打破僵局）
* **Ostrich Algorithm**：鴕鳥演算法（假裝問題不存在，為包含 Linux/Windows 在內的多數現代 OS 採用的策略，將責任轉嫁給開發者）

### 四、 演算法與狀態判定 (Algorithms & State Evaluation)

* **Safe State**：安全狀態（存在一組安全排序，系統有絕對控制權保證所有人完工，絕對無死結）
* **Unsafe State**：不安全狀態（找不到安全排序，死結「有可能」發生，但非必然）
* **Safe Sequence**：安全排序（一組執行緒的排列順序，確保後續者的需求能被目前的閒置資源加前面執行緒歸還的資源所滿足）
* **Total Ordering**：全序排列（死結預防的實務作法：賦予資源整數編號，強制依遞增順序申請以破除循環等待）
* **Banker's Algorithm**：銀行家演算法（用於多重資源實例的死結避免演算法）
* **Available / Max / Allocation / Need**：銀行家演算法四大矩陣（可用資源、最大需求、已分配資源、尚需資源）
* **Claim Edge**：宣告邊（死結避免演算法中代表「未來可能需求」的虛線）
* **Wait-for Graph**：等待圖（刪除資源節點並合併邊緣，用於單一資源實例的死結偵測）

### 五、 復原機制與衍伸問題 (Recovery Mechanisms & Issues)

* **Process / Thread Termination**：行程終止（選擇全殺或一次殺一個來解除死結）
* **Resource Preemption**：資源剝奪（強行搶走某死結行程的資源分給別人）
* **Selecting a Victim**：挑選犧牲者（基於優先權、已用時間、牽連範圍等因素計算最小成本）
* **Rollback / Total rollback**：回滾 / 完全回滾（被剝奪資源的行程必須退回安全狀態或直接重頭執行）
* **Starvation**：飢餓（復原時若只看當下成本，弱勢行程可能永遠被當成肥羊剝奪資源而餓死，解法是將「被回滾次數」加入成本計算）
* **Disjoint cycle**：不相交循環（資源分配圖中完全獨立的多個死結圈，復原時每個圈都必須至少挑選一名犧牲者）
# ch9
### 一、 核心概念與硬體支援 (Core Concepts & Hardware Support)

* **Virtual Memory vs. Physical Memory**：虛擬記憶體與實體記憶體（行程看見的邏輯連續位址空間，與硬體真實的存放位置，兩者透過系統脫鉤）。
* **MMU (Memory Management Unit)**：記憶體管理單元（負責在底層將 CPU 產生的虛擬邏輯位址，動態翻譯成實體位址的硬體裝置）。
* **Base register / Limit register**：基底暫存器與極限暫存器（分別記錄行程合法的「最小實體位址」與「可存取範圍」，由硬體進行越界檢查以實現記憶體保護）。
* **TLB (Translation Look-Aside Buffer)**：轉譯後備緩衝區（內建於 CPU 管線的極速快取，儲存近期的位址映射，用以解決分頁表放在主記憶體所導致的「兩次存取」效能延遲）。
* **PTBR (Page-table base register)**：分頁表基底暫存器（指向存放於主記憶體中的分頁表起點）。
* **ASID (Address-space identifier)**：位址空間識別碼（TLB 條目中的行程身分證，允許 TLB 同時存放多個行程的快取而不必在內容交換時清空）。

### 二、 程式綁定與載入機制 (Binding & Loading Mechanisms)

* **Address Binding**：位址綁定（將程式碼中的邏輯位址轉換為實體位址的過程，可發生在編譯時期、載入時期或執行時期）。
* **Absolute code / Relocatable code**：絕對程式碼（編譯時寫死實體位址）與可重定位程式碼（寫成相對偏移量，可在記憶體中任意放置）。
* **Dynamic Loading**：動態載入（常式只有在真正被呼叫時才會載入記憶體，節省空間，不需 OS 特別支援）。
* **Dynamic Linking / Shared Libraries**：動態連結與共享函式庫（將連結推遲到執行時期，允許多個行程在實體記憶體中共用同一份函式庫副本，需 OS 支援）。

### 三、 連續記憶體配置與演算法 (Contiguous Allocation & Algorithms)

* **Variable-partition scheme**：變動分割機制（實體記憶體依行程需求動態切分大小，每個分割區恰好包含一個行程）。
* **Hole**：記憶體空洞（記憶體中連續的未分配可用空間）。
* **First fit / Best fit / Worst fit**：首次適應（找第一個夠大的）、最佳適應（找剛好夠大中最小的）、最差適應（找最大的空洞配置）。
* **Buddy System**：夥伴系統（將記憶體依 2 的次方進行對半切割與合併的演算法，釋放極快但內部碎裂嚴重）。
* **Next fit (Roving Pointer)**：下次適應（使用漫遊指標，從上次配置的位置繼續環狀尋找空洞，速度快但易切碎後段大空間）。

### 四、 記憶體碎裂現象與對策 (Fragmentation & Solutions)

* **External Fragmentation**：外部碎裂（總剩餘空間足夠，但散落成不連續的小空洞導致無法配置）。
* **Internal Fragmentation**：內部碎裂（為配合固定區塊大小而多給的記憶體，浪費在分割區內部無法被回收）。
* **50% Rule**：50% 規則（統計指出外部碎裂極為嚴重，可能讓系統憑空損失三分之一的記憶體效能）。
* **Compaction**：緊緻化 / 記憶體壓縮（將記憶體內容推擠集中，把零碎空洞合併成大空洞的解法，僅限支援執行時期動態重定位的系統使用）。

### 五、 非連續記憶體配置：分段與分頁 (Segmentation & Paging)

* **Segmentation**：分段機制（支援使用者視角，將程式切為不同邏輯長度的區段如 Stack/Data，易產生外部碎裂）。
* **Paging**：分頁機制（將實體記憶體切成固定大小的 Frames，邏輯記憶體切成 Pages，徹底消滅外部碎裂，但會產生內部碎裂）。
* **Page Table Entries (PTEs)**：分頁表條目（包含實體頁框編號 PFN，以及 Modify 髒位元、Reference 參照位元、Valid/Invalid 有效無效位元等狀態標記）。
* **Reentrant Code / Shared Pages**：可重入程式碼 / 共享分頁（執行期間不變的唯讀程式碼，讓多個行程安全共用同一實體記憶體分頁以節省龐大空間）。
* **Hierarchical Paging**：階層式分頁 / 前向映射分頁表（將龐大的分頁表本身再度進行分頁切割，以解決分頁表佔用過多連續主記憶體的問題）。

### 六、 效能評估指標 (Performance Metrics)

* **Memory Stall**：記憶體停頓（CPU 因等待較慢的主記憶體傳輸資料而產生的閒置週期）。
* **Hit ratio**：命中率（TLB 能成功找對位址映射資料的機率）。
* **EAT (Effective Memory-Access Time)**：有效記憶體存取時間（將 TLB 命中與未命中的狀況，考量 TLB 搜尋時間與記憶體查表時間後，依機率進行加權平均的真實效能指標）。
