Spec 23：同步工具互動示範 ​

目標 ​

輸入 demo sync，由實際行程操作自製 Mutex（互斥鎖）與 Semaphore（號誌），在終端顯示執行步驟與行程狀態，完成後回收行程及同步物件。使用者已明確同意新增示範程式碼。

設計 ​

shell 父行程建立 mutex 和初始值 0 的 semaphore，先持鎖使用共用終端，fork 建立子行程；子行程要求同一個 mutex，父行程觀察 ps 後釋放。子行程取得鎖、在臨界區域輸出、解鎖，再等待 semaphore；父行程再觀察 ps，使用 post 讓子行程繼續。最後 wait 回收子行程，再 destroy 同步物件。子行程繼承同步物件編號；fork 的一般記憶體是私有的，此示範並未實作共享變數或共享記憶體。終端只由示範中遵守同一把鎖的輸出者協調，不能防止其他背景行程輸出。

父行程在兩個階段各 sleep 200 ms，讓子行程有機會運作；ps 是實際快照，不是捏造的狀態。繁忙或異常情況下不保證在快照時已進入等待，且背景輸出可能交錯。行程表最多 4 個欄位；沒有空位時 fork 回 -11，釋放持鎖並回收同步物件。物件額度不足、同步呼叫失敗時回報；成功路徑回收子行程與物件。

實作位於 user/sync_demo.c，使用 WUWAOS 自製 syscall（系統呼叫）介面，不使用 POSIX。shell 與 sync_demo、workstate 使用 Clang -Oz（縮小程式碼）以符合既有四頁使用者程式碼限制，不改頁表布局。

驗收條件與紀錄 ​

  • WSL 建置及網站建置成功；使用獨立 QEMU 磁碟執行 demo sync，觀察 mutex 與 semaphore 兩次 Waiting sync、後續喚醒、子行程退出與回收。
  • 3 個 worker 占滿行程欄位後，demo 顯示 fork -11，worker 回收後可再次成功執行 demo；workstate 可開啟並以 q 離開。
  • 已在 QEMU 執行上述互動。最後修改僅調整示範文字後，再執行 demo 並觀察兩個階段；200 ms 非精確同步保證。未驗證所有同步物件耗盡、裝置故障與所有強制終止情境。

觀念參考 notes/ch6 Synchronization Tools.md；現行同步介面與限制見 Spec 22。
