# 本機與遠端整合（2026-11-10）

本機基底為 `544e202`，未提交工作先保存為 `0803032`；遠端合併來源為 `4177adb`。合併保留雙方提交歷史。

| 範圍 | 本機工作 | 遠端更新 | 合併結果 |
| --- | --- | --- | --- |
| 開機與模組 | 舊版平面目錄、QEMU `-kernel` | 模組分層、flash 載入 WUFS 的 `/boot/kernel.elf` | 保留遠端目錄與兩種開機入口 |
| Block | 明確裝置所有權、完成檢查、計數 | per-device gate/event/bounce、非同步等待、有界 reset/offline | 採遠端生命週期，加上本機診斷計數；IRQ/poll 共用完成檢查 |
| 外部中斷 | 有界 FDT 解析、PLIC 路由與派發 | 以 scheduler polling 收集裝置事件 | 移植為 `arch/riscv/fdt.*` 與 `irq.*`，保留 polling 備援 |
| FS／VM 同步 | 排序 KernelMutex、FIFO ownership handoff | KernelGate、取消延遲、VM pin/revoke、WUFS journal | runtime 使用遠端 gate；mutex 與主機測試保留為獨立原型 |
| 使用介面與文件 | PLIC／請求原型規格 | 多視窗 Terminal、互動教學與網站 | 保留遠端功能，補上整合註記與目前驗證範圍 |

PLIC callback 先 ACK VirtIO，再呼叫共用 `poll_device`，最後由 dispatcher complete PLIC claim。Callback 不睡眠、不輸出、不切換行程、不歸還 DMA buffer；event 通知可把等待者排入 Ready queue。`process_wait_allowed` 拒絕 IRQ context。Kernel 全域中斷及單 hart 政策不變。未支援裝置樹或 PLIC 路由時沿用 polling。

`ps` 顯示 PLIC handled/spurious、unhandled/invalid/budget，以及每顆磁碟的 state、submitted/completed、io_errors/protocol_errors、offline。正常閒置時 submitted/completed 相等；發生 reset/offline 後，失敗提交可能沒有正常 used-ring completion，不保證兩者相等。

本機兩份 Spec 32／33 保留合併前設計背景與原編號；與遠端同號文件以檔名區分。其同步等待、直接 fail-stop 和「尚未編譯」描述屬歷史階段，現況以本文為準。`kernel/proc/kmutex.*` 沒有接入 runtime，不可把它的主機測試當成 FS／VM gate 或 RV64 context-switch 驗證。

編譯時另移除遠端 FS 內只有賦值、沒有讀取的 `format_version`，以通過 portable Clang 23 的 `-Wall -Wextra -Werror`。

## 開機入口

Windows PowerShell 在 `D:\WUWAOS`，使用現有 portable 環境：

```powershell
.\Start-WUWAOS.cmd gui     # 原生 QEMU 圖形視窗
.\Start-WUWAOS.cmd         # UART；QEMU 直接載入核心
```

真正從 WUFS 磁碟載入核心，可先執行 `.\Start-WUWAOS.cmd shell`，再於 Bash 輸入：

```bash
make run-disk
```

該模式使用唯讀 `build/boot-flash.img` 與 `build/wuwaos-cli.img`，由 OpenSBI → flash loader → `/boot/kernel.elf` 啟動 CLI，不使用 QEMU `-kernel`。文字模式按 Ctrl+A，放開後按 X 結束。圖形模式關閉 QEMU 視窗。使用同一映像時先結束前一個 session。
