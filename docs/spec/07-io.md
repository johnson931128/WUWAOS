# 07 · 資料怎麼進出：I/O 與磁碟

<div class="tb-box problem">
<span class="tb-label">本章要解決的問題</span>

鍵盤、序列埠（UART）、虛擬磁碟、Pipe 管線與圖形終端機的硬體介面天差地遠——有的逐字元傳、有的以 512-byte 磁區存取、有的甚至根本不是硬體。如果每個應用程式都要針對每種裝置寫不同程式碼，UNIX 管線（`cat a | wc`）就不可能成立。同時，磁碟速度比 CPU 慢上數個數量級，等待磁碟時該怎麼不浪費 CPU，且在逾時或重設時不讓 DMA 寫壞核心記憶體？
</div>

## 恐龍書核心理論：統一 I/O 抽象、DMA 與中斷驅動

恐龍書第 12 章（I/O Systems）提出兩項基石設計：

1. **Everything is a File（統一描述符介面）**：對應用程式而言，不管背後是磁碟檔案、Pipe 還是終端機，全部透過同一個整數編號——[檔案描述符（FD）](./glossary.md#fd)——呼叫 `read()` / `write()` / `close()`。
2. **Polling vs. Interrupt-Driven I/O + DMA**：
   - **輪詢（[Polling](./glossary.md#polling)）**：CPU 反覆讀取裝置狀態暫存器，實作簡單但等待期間浪費算力（適合早期開機階段）。
   - **中斷驅動 ＋ DMA**：驅動程式把傳輸緩衝區交給裝置後就讓執行緒睡眠；裝置自行透過 DMA 搬運資料，完成後發送硬體中斷（IRQ）通知核心喚醒等待者。

## FD、OFD、Pipe 與終端的分層關係

在 UNIX 與 WUWAOS 中，行程的檔案描述符並不是直接指向檔案，中間還隔了一層 **Open File Description（[OFD](./glossary.md#ofd)）**：

- **FD → OFD**：每個行程有自己的 FD 表；OFD 則保存「物件種類（檔案／Pipe／TTY）與目前讀寫位移（Offset）」。當行程呼叫 `dup()`、`dup2()` 或 `fork()` 時，多個 FD 會指向**同一筆 OFD**，因此會共享同一個讀寫位置；關閉 FD 只是遞減 OFD 的引用計數。
- **Pipe**：核心維護一段固定容量緩衝區。緩衝區空且還有寫端時，讀者讓出 CPU 等待；資料讀完且所有寫端關閉時，`read()` 回傳 `0`（EOF）；沒有讀者卻硬寫則收到 `ERR_BROKEN_PIPE`。Shell 正是靠 `dup2()` 把前一個程式的 stdout（FD 1）接到下一個程式的 stdin（FD 0）。
- **終端（[TTY](./glossary.md#tty)）**：無論是 CLI 的 UART 或桌面版的圖形終端機，都接在同一個 I/O 入口下，核心依端點類型將字元導向序列埠暫存器或圖形視窗。

> 建議搭配 [FD／OFD 互動教學](../topics/file-descriptors.md) 親手操作 `open()`、`dup()` 與 `fork()`，一眼看懂為什麼兩個行程會互相推進對方的檔案位移。

## 一次磁碟讀取的完整路徑（WUWAOS 實例）

當使用者程式呼叫 `read(fd, user_buf, n)` 讀取磁碟檔案時，資料會依序經過四站：

1. **VFS / WUFS 定位磁區**：`io_read()` 找到對應的檔案 OFD，由 [WUFS](./09-filesystem.md) 算出要讀的[磁區](./glossary.md#sector)編號。
2. **提交 VirtIO 請求**：[VirtIO](./glossary.md#virtio) Block 驅動準備包含磁區號、讀寫標記與 DMA 緩衝區的請求，寫入裝置佇列後以 MMIO 通知 QEMU。
3. **讓出 CPU 等待完成**：開機早期可用輪詢等待；排程器啟動後，呼叫者透過核心事件（`KernelEventSource`）進入等待讓出 CPU。裝置完成後由 [PLIC](./glossary.md#plic) 觸發外部中斷，或由輪詢路徑走共用完成驗證。
4. **安全收尾並複製回使用者空間**：呼叫者恢復後收取狀態，再把核心緩衝區資料安全複製回使用者空間（若目標頁為 COW 頁，寫入前會先依[第 08 章](./08-virtual-memory.md)拆分）。

<div class="tb-box wuwaos">
<span class="tb-label">DMA 記憶體安全邊界：請求所有權規則</span>

這是實際寫驅動程式最容易踩到的致命坑：**只要硬體還沒確認停止存取，核心絕對不能釋放或重用 DMA 緩衝區**。WUWAOS 規定每顆 Block 裝置的請求與 bounce buffer 必須持有到完成驗證為止；若發生逾時，必須先確認裝置已安全重設才隔離裝置並回錯——若無法確認裝置停止寫入，核心寧可停機保護記憶體，也不讓未知 DMA 靜默破壞其他頁框。
</div>

### 讀取結果要看回傳長度

請求讀 32 bytes 時，Pipe 目前可能只有 8 bytes。讀者先處理已回傳的部分，下一次讀取再依剩餘資料與寫端狀態前進。若 Pipe 已空且最後一個寫端關閉，讀 0 bytes 代表到達末尾。磁碟路徑則要看檔案位移、讀取長度和裝置結果。 [Pipe 讀寫](https://github.com/johnson931128/WUWAOS/blob/main/kernel/io/io.c#L368) · [裝置完成處理](https://github.com/johnson931128/WUWAOS/blob/main/drivers/virtio/block.c#L372)
