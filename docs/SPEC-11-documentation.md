# Spec 11：依主題分類的 WUWAOS 文件網站

## 目標

將使用者既有實作規格與程式碼說明整理為類似《1000 行作業系統》的文件網站。使用者不需要具備前端開發經驗，日常以 Markdown 編輯內容。

## 工作範圍與設計

- 第一階段已完成本機預覽；後續使用者授權公開部署，並要求 GitHub 為唯一來源、沒有公開來源切換或編輯功能。僅發布文件與靜態網站，不提交 main 的 OS 工作，不新增測試程式碼。
- VitePress 1.6.4，以 docs 為內容根目錄，沿用既有 Markdown 規格而不搬移檔案。
- 以 npm overrides 固定 Vite 6.4.5，替換預設 Vite 5 的已知開發伺服器漏洞依賴；仍需完成實際相容性驗證。伺服器只綁定本機 127.0.0.1。
- 左側主題導覽、中間文章、右側頁內目錄；提供本機搜尋、深淺色與行動版選單、上一章／下一章。
- 主題涵蓋環境、開機、例外與系統呼叫、行程、排程、實體頁／Sv39、按需分頁與 Swap、I/O、WUFS、Shell／fan、網站維護。
- 歷史索引標示早期架構被取代的範圍；現行記憶體說明以 Spec 10 為準。保留原始規格檔作為開發與驗收紀錄。
- 使用者確認文章不展示 OS 程式碼，改放 GitHub 連結；移除原先 snippet 匯入，尚未提交的 Spec 10 程式碼標示版本差異，不建立無效連結。課程筆記只標明引用來源，不複製全文到網站。
- 僅調整技術文件的字體、留白與綠色主題，不複製參考網站文章或商標素材。
- 公開網站使用 GitHub Pages 的 gh-pages 分支；文件來源保存於 codex/documentation 分支。網站沒有內容寫入 API、編輯器、來源選擇或部署 token；修改僅依 GitHub repository 權限管理。前端 HTML／CSS／JavaScript 產物仍須供瀏覽器讀取。
- 發布工具固定 origin 與目的分支、使用獨立暫存索引，保留 main／工作樹／現有暫存內容，不強制覆寫遠端。原始文件與靜態產物均只儲存於 GitHub，不使用其他網站建置服務。
- 提供正式 canonical、網站地圖與可索引靜態 HTML；Google 抓取與收錄時程不保證。子路徑 robots.txt 不取代網域根路徑規則，不更動使用者個人網站。

## 執行步驟

1. 檢查既有規格、程式碼導覽與 Git 狀態，保留前一階段未提交變更。
2. 新增本機 npm 腳本、固定依賴、VitePress 導覽／主題與忽略產物設定。
3. 撰寫依功能分類的章節與歷史索引，串接原規格與來源碼。
4. 完成網站建置，檢查內部連結與頁面生成，實際瀏覽導覽／搜尋／主題切換。
5. 更新根 README 的本機使用方式與此規格的驗收結果。

## 驗收條件

- Windows PowerShell 可安裝依賴，執行 docs:dev／docs:build／docs:preview。
- 章節可導覽，歷史規格可直接閱讀；建置不得忽略斷鏈。
- 原始碼只提供 GitHub 連結，術語附中文用途，明確區分目前設計、公開版本與歷史驗收。
- 在瀏覽器觀察主要頁面、程式碼、搜尋與外觀切換，列出沒有驗證的部分。
- 核心與使用者程式不因本次文件工作改動，沒有新增測試程式碼。
